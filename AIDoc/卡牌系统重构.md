# 卡牌系统重构记录

> 基于对 `Assets/CardRelated/` 代码的 review，记录发现的问题及重构方向。

---

## 已发现的问题

### 1. MoveToHandFromPosition 动画 Bug（Card_1/HandCardUI.cs）

**问题：** 目标位置和起始位置是同一个点，动画不会有任何效果。

```csharp
rectTransform.position = startWorldPosition;         // 设置起始
Vector3 targetPosition = rectTransform.position;     // ← target == start！
rectTransform.position = startWorldPosition;         // 重复设置（无意义）
moveTween = rectTransform.DOMove(targetPosition, duration); // 从A移动到A
```

**修复方向：** 先记录目标位置，再设置起始位置（参考同文件里 `MoveToHandFromScreenPosition` 的正确写法）。

---

### 2. ForbiddenAreaHelper Gizmos 倍数错误（Card_1/ForbiddenAreaHelper.cs）

**问题：** Scene 视图里绘制的区域是实际大小的 100 倍，视觉上完全不准。

```csharp
Gizmos.DrawCube(areaCenter, areaSize * 100);   // ← 应该是 areaSize
Gizmos.DrawWireCube(areaCenter, areaSize * 10); // ← 应该是 areaSize
```

**修复方向：** 去掉乘数，直接用 `areaSize`。

---

### 3. AreaMaterialOverlay 拖拽时内存泄漏（Card_1/AreaMaterialOverlay.cs、Card_MVC/CardAreaMaterialOverlay.cs）

**问题：** `renderer.materials`（注意不是 `sharedMaterials`）的 setter 每次调用都会在内存里创建新的材质实例，且不会自动释放。拖拽过程中每帧都调 `ShowAreaEffect`，持续泄漏。

```csharp
renderer.materials = newMaterials; // 每帧调用 → 每帧产生新的材质实例
```

**修复方向：** 改用 `MaterialPropertyBlock`，参考同项目 `CardPlacementIndicator.cs` 里的正确做法。

---

### 4. CardGameManager 初始化时序问题（Card_MVC/Manager/CardGameManager.cs）

**问题：** `CardGameManager.Start()` 调用 `ConnectToManagers()` 时读取 `PlayerHandManager.Instance.HandCards`，但 `PlayerHandManager.Start()` 里才初始化手牌。两个 MonoBehaviour 的 `Start` 执行顺序不确定，CardGameManager 先跑时卡牌池为空，Controller 拿不到任何卡牌数据。

```csharp
// CardGameManager.Start()
var cardPool = PlayerHandManager.Instance.HandCards; // ← PlayerHandManager.Start() 可能还没跑
```

**修复方向：** 用 Script Execution Order 保证 PlayerHandManager 先初始化，或将卡牌池初始化改为显式调用而不是依赖 Start 顺序。

---

### 5. 双份手牌状态不同步（架构问题）

**问题：** `PlayerHandManager.handCards`（驱动旧版 CardUISystem）和 `PlayerHandModel.m_Cards`（驱动新版 CardUIForm）是两份完全独立的数据，CardGameManager 没有做双向同步。

- 通过 Controller 抽的牌 → 只更新 PlayerHandModel → 旧版 UI 不知道
- 通过 Manager 抽的牌 → 只更新 PlayerHandManager.handCards → 新版 UI 不知道

同样的问题也存在于 PopulationManager 和 PopulationModel 之间。

**修复方向：** 二选一，不要并行维护两份状态。要么彻底切到 MVC Controller 驱动，删掉 Manager 里的状态；要么让 Manager 作为 Controller 的薄包装，状态只存一份在 Model 里。

---

### 6. CardUISystem.OnHandChanged 状态机容易失同步（Card_MVC/UI/CardUISystem.cs）

**问题：** 用 `lastHandCount` + `isAddingCards` flag 控制 UI 刷新，协程运行期间收到的所有 `OnHandChanged` 事件直接跳过，连续快速抽牌或有任何延迟时 UI 会少显示卡牌。

```csharp
else if (currentCount > lastHandCount && !isAddingCards) {
    isAddingCards = true;
    StartCoroutine(AddCardsIncremental(...));
    // 协程期间再触发的变化全部被丢弃
}
```

**修复方向：** 不要用 flag 跳过事件，改为每次 OnHandChanged 都重新 diff 当前 UI 列表和数据列表，只增删差异部分。

---

### 7. EventId 使用 GetHashCode() 不稳定（Card_MVC/Event/CardEventArgs.cs）

**问题：** 理论上不同类型的 HashCode 可能碰撞，跨平台/版本也不保证一致。和项目其他事件的自增数字 ID 不统一。

```csharp
public static readonly int EventId = typeof(CardDrawnEventArgs).GetHashCode();
```

**修复方向：** 改为和项目其他事件统一，使用固定自增数字 ID。

## 优先级

| 优先级 | 问题 | 影响 |
|--------|------|------|
| 高 | 3. AreaMaterialOverlay 内存泄漏 | 每帧拖拽产生内存泄漏 |
| 高 | 4. CardGameManager 时序 | 初始化失败，卡牌池为空 |
| 高 | 1. MoveToHandFromPosition 动画 Bug | 抽牌动画完全无效 |
| 中 | 5. 双份状态不同步 | 两套 UI 显示不一致 |
| 中 | 6. OnHandChanged 状态机 | 快速操作时 UI 丢牌 |
| 低 | 2. ForbiddenAreaHelper Gizmos | 仅影响编辑器显示 |
| 低 | 7. EventId GetHashCode | 理论风险，实际极少触发 |
