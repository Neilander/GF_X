CardRelated 文件夹解析

路径：Assets/CardRelated/AAAGame/Scripts/  ·  队友贡献的卡牌系统，包含两个版本

整体概览

该文件夹包含一个完整的卡牌系统，作者经历了两个版本的迭代：

Card_1 — 原版拖拽

快速原型版本，单一脚本直接驱动。核心逻辑、UI、数据耦合在一起，适合验证功能可行性。

无命名空间 全局单例 逻辑耦合 MonoBehaviour驱动 可直接挂场景

Card_MVC — MVC重构版

用 MVC 模式重构，数据/逻辑/显示分层。同时提供两套入口：GF UIForm 版本和独立 MonoBehaviour 版本。

namespace AAAGame.Card MVC分层 接口抽象 兼容旧版 GF事件驱动

核心设计意图： CardGameManager（MonoBehaviour）作为唯一入口，持有 CardSystemController（纯C#），再由 Controller 驱动 Model。UI 层只读 Model、响应 GF 事件，不直接修改数据。Manager 层的 PopulationManager / PlayerHandManager 是为了兼容旧 Card_1 的 UI 代码而保留的桥接层。

Card_1 — 原版文件详解

数据
CardData.cs ScriptableObject
卡牌配置数据资产。字段包括 cardName、populationCost（人口消耗）、soldierCount（生成数量）、soldierPrefab（生成Prefab）、spawnRadius（生成半径）、dropWeight（抽卡权重）。

GetCardData() 方法当前直接返回 this，注释里留有 TODO：将来改为通过 index 查 DataTable。
Card_1 版本中此文件全部注释掉了，改用了 Card_MVC/Data/CardData.cs（内容相同但激活状态）。两个文件同名会引起命名空间冲突，接入时需要注意。
CardEventArgs.cs C# class
Card_1 版的事件参数定义（未使用 GF ReferencePool）。具体内容未读，但可类比 MVC 版的 CardEventArgs。
UI / 交互
HandCardUI.cs MonoBehaviour
单张手牌的 UI 组件。实现了完整的拖拽接口（IBeginDragHandler / IDragHandler / IEndDragHandler）和悬停放大效果，用 DoTween 做动画。
  • 拖拽开始：脱离手牌容器移到 Canvas 顶层，通知 CardUIManager
  • 拖拽结束：询问 CardUIManager.OnCardEndDrag，失败则用 DOMove 弹回原位
  • MoveToHandFromScreenPosition()：从指定屏幕位置飞入手牌区（抽牌动画）
  • 人口不足时 CanvasGroup.alpha = 0.5f 置灰
CardUIManager.cs MonoBehaviour
Card_1 版的总管理器。文件过大（约400行），是整个 Card_1 系统的核心：负责初始化手牌UI、处理拖拽事件、射线检测地面位置、检测禁止区域、调用 SoldierFactory 生成士兵。包含 TestDrawCards() 和 TestAddCards() 供编辑器测试按钮调用。
Singleton 模式，其他组件（如 HandCardUI、CardUIDebugger、CardUITestProcedure）均通过 CardUIManager.Instance 访问。
管理器
PlayerHandManager.cs MonoBehaviour
管理玩家手中持有的卡牌列表。Start 时从 cardPool（Inspector 配置的 ScriptableObject 列表）按权重随机抽取 maxHandSize（默认4）张初始手牌。
  • DrawRandomCards(count) — 按 dropWeight 加权随机抽卡
  • AddCard / RemoveCard / RemoveCardAt — 增删手牌并触发 OnHandChanged 事件
  • RedrawHand() — 清空后延迟一帧重新随机抽取（保证UI清空再重建）
PopulationManager.cs MonoBehaviour
人口资源管理器。维护 currentPopulation / maxPopulation 两个字段，对外暴露 AvailablePopulation = max - current。
  • HasEnoughPopulation(cost) — 检查是否够用
  • OccupyPopulation(cost) — 消耗人口（不足则返回 false）
  • ReleasePopulation(cost) — 释放人口（士兵死亡时调用）
  • 人口变化时触发 OnPopulationChanged(current, max) 事件
视觉反馈 / 放置指示
CardPlacementIndicator.cs MonoBehaviour
3D 世界空间里跟随鼠标的放置指示器（扁平圆柱体）。通过 MaterialPropertyBlock 设置颜色（绿色=合法，红色=禁止），不创建新材质实例。拖拽过程中由 CardUIManager 每帧调用 UpdatePosition() 和 SetValid()。
AreaIndicator.cs MonoBehaviour
区域光效指示器，使用 DoTween 淡入/淡出动画。维护两个子对象（validAreaIndicator / invalidAreaIndicator），通过 MaterialPropertyBlock 的 _BaseColor 和 _EmissionColor 做透明度渐变。
拖拽时调用 Show(valid)，拖拽结束调用 Hide()。
AreaMaterialOverlay.cs MonoBehaviour
材质叠加器。通过在 Renderer 的 materials 数组末尾追加一个叠加材质（绿色/红色半透明），实现地面区域高亮。在 Awake 时缓存所有原始材质，切换区域时先恢复再重新追加。
  • 用 collider.ClosestPoint(worldPos) 判断点是否在区域内（支持不规则形状）
  • HideAreaEffect() 恢复所有 Renderer 的原始材质
编辑器辅助 / 调试工具
ForbiddenAreaHelper.cs MonoBehaviour [ExecuteInEditMode]
编辑模式可视化工具，在 Scene 视图用 Gizmos 绘制禁止区域的边界框、8个角点和坐标轴。提供 ContextMenu 快捷操作（应用到 Transform / 从 Transform 读取 / 扩大缩小）。开启 autoApplyToTransform 时，编辑器模式每帧自动把参数写入 Transform。
AreaDebugger.cs MonoBehaviour
运行时区域系统诊断工具。按 F2 打印 CardUIManager 的 forbiddenArea 配置、AreaMaterialOverlay 配置、材质引用情况。持续按住鼠标左键时打印当前鼠标位置及是否在禁止区域。OnDrawGizmos 绘制区域边界。
大量使用反射读取私有字段，仅供调试使用。
CardUIDebugger.cs MonoBehaviour
卡牌 UI 配置诊断工具。按 F1 打印 CardUIManager 状态、卡牌预制体结构（反射检查 HandCardUI 的三个 UI 引用）、场景中所有 HandCardUI 实例的卡牌数据、PlayerHandManager 手牌列表。
CardUITestProcedure.cs ProcedureBase
GameFramework 测试流程。进入时通过代码创建 ForbiddenArea（红色半透明立方体）和 PlacementIndicator（圆柱体），并检查 PopulationManager / PlayerHandManager 是否已在场景中。
快捷键：R 重置人口和手牌，ESC 返回 MenuProcedure。
此 Procedure 未注册到项目流程列表（UIprocedure.cs 全部注释）。接入时需要手动添加。

Card_MVC — MVC重构版文件详解

Data 层 — 数据抽象与来源
ICardDataProvider.cs Interface
系统的核心抽象接口。定义所有卡牌数据的只读契约，包含：CardId, CardName, CardSprite, PopulationCost, SoldierCount, SoldierName, SoldierPrefab, SpawnRadius, CardColor, DropWeight, GetDisplayInfo()。
这个接口是整个系统可扩展的关键。目前数据来自 ScriptableObject，将来只需换一个实现类（如 CardDataTableAdapter），上层 Model/Controller 完全不用改。
CardData.cs ScriptableObject
和 Card_1 版内容几乎一致，但这个版本是激活的。[CreateAssetMenu] 可在 Project 右键创建资产。GetCardData() 当前返回 this，留有 DataTable TODO。
CardDataAdapter.cs C# class
适配器模式，将 CardData（ScriptableObject）包装为 ICardDataProvider。所有属性转发到内部 m_CardData。由 CardGameManager.ConnectToManagers() 在运行时创建，将 PlayerHandManager 里的旧 CardData 列表批量转换为接口列表传给 Controller。
CardDataTableAdapter.cs C# class
DataTable 适配器，实现 ICardDataProvider，从 GF DataTable 读取卡牌数据（对应 DRCard 行）。目前是为将来接入数据表准备的占位实现，暂未实际使用。
DRCard.cs C# class
DataRow 定义，对应 DataTable 中的卡牌数据行。字段与 CardData ScriptableObject 一一对应，供 CardDataTableAdapter 使用。
CardDataProviderFactory.cs C# class
工厂类，根据配置决定创建哪种 ICardDataProvider 实现（ScriptableObject 版或 DataTable 版）。统一提供数据获取入口。
Model 层 — 纯数据，无 Unity 依赖
CardModel.cs C# class（非MonoBehaviour）
单张卡牌的运行时模型。持有 ICardDataProvider（只读数据）和 PopulationModel（人口状态引用）两个依赖。
  • CanPlay() — 委托给 PopulationModel.HasEnoughPopulation(dataProvider.PopulationCost)
  • 提供 GetCardId / GetCardName / GetPopulationCost 等快捷访问
CardModel 不持有位置、不持有 GameObject，只关心"这张牌能不能打"和"这张牌是什么"。
PlayerHandModel.cs C# class（非MonoBehaviour）
手牌集合的数据模型，内部是 List<CardModel>，上限 MaxCards（默认来自 CardConst.MaxHandCards = 4）。提供 AddCard / RemoveCard / RemoveCardAt / GetCard / GetAllCards / Clear / Contains / IndexOf 等基础操作，不含任何副作用。
PopulationModel.cs C# class（非MonoBehaviour）
人口资源的数据模型。m_CurrentPopulation 随消耗增加、随恢复减少（和 Card_1 版逻辑相同）。
  • ConsumePopulation(amount) — 消耗，内部 current += amount
  • RestorePopulation(amount) — 恢复，内部 current -= amount
  • GetPopulationUsageRatio() — 返回 0~1 使用率，供 PopulationView 决定警告颜色
Controller 层 — 业务逻辑，纯C#
CardSystemController.cs C# class（非MonoBehaviour）
主控制器，整个 MVC 系统的调度中心。持有所有子 Controller 和 Model 的引用，对外暴露统一的操作接口。
  • Initialize() — 创建 PopulationModel、PlayerHandModel、HandCardController、CardPlacementController、AreaDetectionController
  • DrawCard() / DrawCards(count) — 按权重随机抽牌，调用 HandCardController.DrawCard()，成功后触发 OnCardDrawn 事件
  • PlayCard(cardModel) — 检查是否可打，然后进入放置流程
  • StartPlacement / UpdatePlacement / ConfirmPlacement / CancelPlacement — 完整放置生命周期，ConfirmPlacement 成功后消耗人口、移除手牌、触发 OnCardPlayed
  • DiscardCard() — 移除手牌并触发 OnCardDiscarded
HandCardController CardPlacementController AreaDetectionController PlayerHandModel PopulationModel
HandCardController.cs C# class（非MonoBehaviour）
手牌控制器，专注于卡牌的添加和移除。DrawCard(ICardDataProvider) 创建 CardModel（注入 PopulationModel 引用）并加入 PlayerHandModel，成功后触发 OnCardDrawn 事件。RemoveCard / RemoveCardAt 从模型删除后触发 OnCardRemoved。
CardPlacementController.cs C# class（非MonoBehaviour）
卡牌放置控制器。维护一个放置状态机（m_IsPlacing）和当前位置 m_CurrentPlacementPosition。
  • 射线检测：TryGetGroundPosition() 向 Ground 层发射射线
  • 合法性检测：CheckPlacementValidity() 用 Physics.OverlapSphere 检测 ForbiddenArea 层
  • 士兵生成：SpawnSoldiers() 在圆形区域内随机分布 Instantiate
  • 每帧调用 UpdatePlacement()，位置或合法性变化时触发 OnPositionUpdated / OnValidityChanged
SpawnSoldiers 直接 Instantiate soldierPrefab，未接入项目的 GF Entity 系统 / SoldierFactory，接入时需要对接。
AreaDetectionController.cs C# class（非MonoBehaviour）
区域检测控制器。缓存可放置区域和禁止区域的 Collider 数组（m_AreaColliderCache），用 ClosestPoint 方式判断点是否在区域内（distance < 0.01f 视为内部）。同时提供基于 Layer 的 Physics.OverlapSphere 检测方式。暴露 DetermineAreaType() 返回 AreaType.Valid/Invalid/None。
Manager 层 — 桥接层，兼容旧 UI

Manager 层的核心职责是桥接：让旧版 CardUISystem（直接依赖 Singleton Manager）和新版 MVC 架构可以共存。

CardGameManager.cs MonoBehaviour（Singleton）
整个 MVC 卡牌系统的场景入口。Start 时：
  1. 创建并初始化 CardSystemController
  2. 调用 ConnectToManagers() 将 PopulationManager / PlayerHandManager 与 CardSystemController 双向绑定
  3. 订阅 Controller 的所有事件，转发给 Manager
Update 每帧调用 cardSystemController.UpdatePlacement()。对外暴露简单的 DrawCards / PlayCard / StartPlacement / ConfirmPlacement / CancelPlacement / DiscardCard 接口。
PlayerHandManager.cs MonoBehaviour（Singleton，namespace AAAGame.Card）
MVC 版的手牌 Manager，和 Card_1 版接口几乎相同（AddCard / RemoveCard / DrawRandomCards 等），但多了 SetCardSystemController() 方法供 CardGameManager 注入依赖。OnHandChanged 事件被 CardUISystem 订阅以刷新 UI。
和 Card_1 的 PlayerHandManager 同名！两个都在 global 命名空间下（MVC 版有 namespace 但 Card_1 版没有），可能引起歧义。实际使用时应明确是哪个版本。
PopulationManager.cs MonoBehaviour（Singleton，namespace AAAGame.Card）
MVC 版人口 Manager。逻辑与 Card_1 版相同，额外增加了 SetCardSystemController() 注入，在 SetMaxPopulation() 时同步到 Controller 的 PopulationModel。
UI 层 — 两套入口并存

GF UIForm 版本

CardUIForm + HandCardItem
集成到 GF UI 系统，通过 GFBuiltin.Event 响应事件

独立 MonoBehaviour 版本

CardUISystem + CardHandUI
不依赖 GF UIForm，直接在 Scene 中挂载

CardUIForm.cs UIFormBase（GF UIForm）
符合 GameFramework UI 规范的卡牌界面。OnInit 时订阅4个 GFBuiltin 事件（CardDrawn / CardPlayed / CardDiscarded / PopulationChanged）；OnOpen 收到 CardSystemController 作为 userData，初始化 PopulationView 和手牌 UI 列表。
  • 手牌区：Instantiate handCardItemPrefab 并调用 HandCardItem.Initialize(cardModel, this)
  • 拖拽回调：OnCardBeginDrag/Dragging/EndDrag，EndDrag 先判断垃圾桶区域，再调 CardSystemController.ConfirmPlacement
  • 快捷键：数字1-4打出对应索引的手牌
使用 GFBuiltin.Event 而非项目的 GF.Event，接入前需确认两者一致或做适配。
HandCardItem.cs MonoBehaviour（配合 CardUIForm）
GF 版的单张手牌 UI 项。通过 Initialize(CardModel, CardUIForm) 初始化，数据来自 ICardDataProvider（通过 CardModel.DataProvider 访问）。拖拽结束后将事件委托给 CardUIForm.OnCardEndDrag，由 Form 决定是否成功放置（成功后由 Form 负责销毁）。
CardUISystem.cs MonoBehaviour（Singleton，独立版）
独立版 UI 总管理器，不依赖 GF UIForm。Start 时订阅 PlayerHandManager.OnHandChanged 和 PopulationManager.OnPopulationChanged 事件，调用 RefreshHandUI 初始化 UI。
  • 抽牌动画：PlayDrawCardAnimation 协程，等待2帧后调用 CardHandUI.MoveToHandFromScreenPosition()
  • 拖拽时更新区域材质效果（UpdateAreaMaterialEffect），射线检测地面，判断是否在禁止区域
  • 拖拽结束判断：手牌区 → 原路返回；垃圾桶 → 丢弃；地面 → 放置生成士兵
  • 快捷键1-4选卡 + 鼠标左键确认使用
  • Tab 键显示/隐藏整个 UI
SpawnSoldiers 直接 Instantiate cardData.soldierPrefab，未接入项目的 GF Entity / SoldierFactory。
CardHandUI.cs MonoBehaviour（配合 CardUISystem）
独立版单张手牌 UI，逻辑与 Card_1 的 HandCardUI.cs 基本一致，但通知对象是 CardUISystem.Instance。增加了 IsDragging 属性供外部查询。
CardAreaMaterialOverlay.cs MonoBehaviour
MVC 版材质叠加器，逻辑和 Card_1 版的 AreaMaterialOverlay 相同，但挂在 Card_MVC 命名空间下，由 CardUISystem 持有引用。拖拽过程中实时调用 ShowAreaEffect(worldPos, isValid)，拖拽结束调用 HideAreaEffect()。
PopulationView.cs MonoBehaviour（namespace AAAGame.Card）
人口显示 UI 组件，配合 GF 版 CardUIForm 使用。Initialize(PopulationModel) 注入模型引用并订阅 PopulationChangedEventArgs GF 事件。支持三个 TMP 文本字段（合并/当前/最大）和超过 warningThreshold（默认80%）时自动切换警告色。
Event 层 — GF 事件定义
CardEventArgs.cs C# 8个 GameEventArgs 子类
全部使用 GF ReferencePool 管理（ReferencePool.Acquire<T> 分配，Clear() 清零字段）。
  • CardDrawnEventArgs — 抽到卡牌（携带 CardModel）
  • CardPlayedEventArgs — 打出卡牌（携带 CardModel）
  • CardDiscardedEventArgs — 丢弃卡牌（携带 CardModel）
  • PopulationChangedEventArgs — 人口变化（current, max, changeAmount）
  • CardPlacementStartEventArgs — 开始放置（携带 CardModel）
  • CardPlacementPositionUpdateEventArgs — 放置位置更新（Position, IsValid）
  • CardPlacementValidityChangeEventArgs — 合法性切换（IsValid）
  • CardPlacementConfirmEventArgs — 放置确认（CardModel, Position）
  • CardPlacementCancelEventArgs — 放置取消
  • CardSoldiersSpawnedEventArgs — 士兵生成（CardModel, SpawnPosition, SoldierCount）
EventId 用 typeof(T).GetHashCode()，而项目其他系统用自增 ID。接入时需要确认是否冲突（概率极低但存在）。

CardEventManager.cs C# class

接入项目的适配清单

已知需要处理的问题
1. UIViews ID 冲突
CraftingDialog = 11 和 CardUIForm 需要的 ID 冲突。需在 UIViews.cs 加 CardUIForm = 16（或其他空闲ID），同步到 UITable.txt。
2. GFBuiltin.Event vs GF.Event
CardUIForm / PopulationView 用 GFBuiltin.Event，项目其他地方用 GF.Event。需确认两者是否为同一实例，或统一改为 GF.Event。
3. 士兵生成未接入 SoldierFactory
CardPlacementController 和 CardUISystem 里 SpawnSoldiers 直接 Instantiate prefab。需改为调用 SoldierFactory.ShowSoldier() 走 GF Entity 流程，支持对象池和 Buff 系统。
4. CardUITestProcedure 未注册
UIprocedure.cs 全注释，需在 ProcedureLaunch 里注册 CardUITestProcedure 才能进入。
5. CardData 同名冲突
Card_1 版 CardData.cs 已注释，MVC 版是无 namespace 的全局类。两个文件同名，确认 Card_1 版保持注释状态即可。
6. Prefab / Scene 引用需重建
CardUISystem.cardUIPrefab、handCardContainer 等所有 Inspector 引用在复制文件夹后丢失，需要在 Unity 中重新拖拽配置。
