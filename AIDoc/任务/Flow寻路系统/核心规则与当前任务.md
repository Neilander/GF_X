# Flow 寻路系统：核心规则与当前任务

## 恢复卡片

- 主线：解决 Lv2 多兵追击窗口的 Flow 主线程尖峰，完成架构、功能和同入口性能验收后才能收尾。
- 当前：停止追踪约 `1ms` 的未归属项；性能主线只处理已实证、会随 source/unit 数放大的 `>3ms` 主体，禁止以汇报或压缩停线。
- 最新固定入口实证（2026-09-02）：`RESULT=PASS`，最大真实单 Tick `25.221ms`（logic=82）；NavigationSync `10.545ms`、Brain `11.429ms`。明确热点为 PathAdvance `10.841ms`、PathSliceComplete `5.230ms`、FlowTileCommitQueueScan `3.396ms`、CombatApproachCore `9.191ms/8 units`。
- 建造指令链取证（2026-09-02）：`LogicFrameCommandCardPlacement=12.6–13.3ms` 并非建造/寻路；`LogicCardPlacementAuthority.ApplyFrame` 在命令段内同步移动单位视野源。主要耗时 `DirtyEntities=10.6–11.1ms`，其中 `VisibilityCollect=9.9–10.3ms`（`FogVisibilityCollectCenter=6.5–7.3ms` 的几何缓存/FOV 构建或命中处理，`CollectIntervals=3.0–3.3ms` 的半径内 Fix64 逐格扫描），其次 `Coverage=1.8–2.4ms`（覆盖差分逐脏行逐格提交）。该 scope 命名是历史耦合，不能再把它当作卡牌放置或寻路耗时。
- 已锁定根因一：multi-source path request 提交仍在一个 operation 内同步遍历所有 source，并逐 source enqueue tile、更新 fixed portal participation；后续集中阶段又扫描 agent 做同类 tile demand，存在重复权威工作。
- 已锁定根因二：Flow tile 的 PortalSlots/authority/copy/publish 仍在主线程按批量 quota 连续执行，单 Tick queue scan 超过 `3ms`。
- 已锁定根因三：同一 target 的多兵首次接敌仍逐 unit 全量扫描攻击槽，8 units 共 708 次 occupancy 查询；共享几何缓存没有消除 `O(units * slots)` 的评分和占用工作。
- 当前拆分验收门槛：不再拆 `~1ms` remainder；直接消除上述 `>3ms`、随规模放大的架构性工作，保持确定性结果、顺序、哈希和 Replay 不变。禁止降 quota、零速补偿、同步补完或 fallback。
- 下一步：先把 path commit 改为单一集中权威路径并补等价性测试；再迁移 Flow tile 主线程批处理；最后实现 target-centric/shared combat slot assignment。每项均经强制 Refresh/compile、专项测试和固定 Lv2 入口复测后推进。
- 门禁：`LogicFrameTick P99 <= 8.33ms`、单 Tick `<=16.67ms`；Flow 合计 `P99 <=4ms`、单 Tick `<=8ms`。不 Build，不以汇报作为停点。 

## Play 测试门禁

- 每次 Play 前必须强制 Unity `Refresh(all)`，请求脚本编译，并等待 `is_compiling=false`、`is_domain_reload_pending=false`、`ready_for_tools=true`；门禁未满足不得进入场景或引用新脚本。

## 不可变规则

1. 先对照 Chapter 23 和当前权威链锁定架构根因，再实现完整主线；禁止从单个热点做表层补偿。
2. 一个有状态 multi-source path request 负责同组 source；目标侧 connector/route/policy 只做一次，source 通过 merging A* 接入。
3. graph/route/tile 所有高层工作按真实 operation quota 跨 Tick 执行；quota 只改变完成 Tick，不改变 route、payload、authority hash 或 replay。
4. request 未完成时只能是显式 `PendingNavigation`，不得读旧 handle、旧方向、旧目标或同步补完。
5. moving target 同 sector 只更新 local binding；跨 sector/dirty topology 只失效必要 suffix/层级。
6. portal-window tile 身份为 `(world, agent type, sector, exit portal, dirty version)`；exact final goal 只属于 final tile，route 只属于 PathHandle。
7. NavigationSync/MoveIntent 不得同步全量 hierarchy、portal A* 或 required tile force commit；UI、准星、镜头等显示交互不走逻辑帧，只有命令提交进入 Tick。
8. 核心导航权威使用 Fix64/raw；异常状态明确报错，不 fallback、不静默跳过。
