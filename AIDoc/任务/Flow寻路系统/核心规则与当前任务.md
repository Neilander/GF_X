# Flow 寻路系统：核心规则与当前任务

## 必读原则

- **极简原则**：本卡只保留当前规则、当前任务和验收门禁；历史证据、过程和失败方案只写入[历史记录](./历史记录.md)，按需读取，不复制流水账。
- **根因原则**：大项必须拆到真实运算，100%确认根因再优化，不猜着改。
- **聚焦原则**：每轮只追一个已确认的毫秒级大项；固定读该项最小调用链，完成拆分或根因闭环前不切换目标、不重复泛读大文件。
- **上下文原则**：优先使用现有日志与历史证据；只读取当前算式所缺的最小片段，禁止为补背景泛读大文件。
- 主线未闭环、任务未完成不得停止工作、收尾或汇报。
- 禁止降 quota、fallback、零速、同步补完或静默跳过掩盖问题；异常必须明确报错。

## 不可变架构规则

1. 同组 source 使用一个有状态 multi-source request；目标侧 connector/route/policy 只做一次，source 通过 merging A* 接入。
2. graph/route/tile 高层工作按真实 operation quota 跨 Tick 执行；quota 只影响完成 Tick，不改变结果或权威数据。
3. request 未完成只能是显式 `PendingNavigation`，不得读旧 handle、方向、目标或同步补完。
4. moving target 同 sector 只更新 local binding；跨 sector 或 dirty topology 仅失效必要 suffix/层级。
5. portal-window tile 身份为 `(world, agent type, sector, exit portal, dirty version)`；exact goal 只属于 final tile，route 只属于 `PathHandle`。
6. `NavigationSync`/`MoveIntent` 不同步全量 hierarchy、portal A* 或 required-tile force commit；UI、准星、镜头等显示交互不进逻辑帧，只有技能施放、移动、建造等命令提交进入 Tick。
7. 核心导航权威使用 `Fix64`/raw。
