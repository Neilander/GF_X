# Flow 寻路系统：核心规则与当前任务

## 必读原则

- **极简原则**：本卡只保留当前规则、当前任务和验收门禁；历史证据、过程和失败方案只写入[历史记录](./历史记录.md)，按需读取，不复制流水账。
- **根因原则**：先做现象级取证，再拆到真实运算；必须拆分到100%确认根因再优化，不猜着改。
- 主线未闭环不得停线、收尾或以汇报代替实现。
- 禁止降 quota、fallback、零速、同步补完或静默跳过掩盖问题；异常必须明确报错。

## 当前任务

- 唯一主线：解决 Lv2 多兵追击的 Flow 主线程尖峰。
- 只处理五项：`DemandResolve`、`DemandDispatch`、`PathQueueBatch`、`SlotCacheBuild`、`OccupancyPreparation`；其他 profiler scope 暂停。
- 当前实证基线：固定入口最大真实单 Tick 约 `29.6ms`；`PathQueueBatch` 约 `6.8ms`，其余四项当前约 `3ms` 内但仍需完成叶级取证和稳定性验证。
- 下一步优先拆解上述五项内部真实循环（尤其 enqueue/queue mutation、slice 状态机、bucket/slot preparation），直到所有叶项 `<3ms`，或找到不可再拆且已 100% 证实根因的 `>3ms` 运算，再实施针对性优化。
- 保持确定性结果、顺序、authority hash、Replay、Pending 和既有功能契约不变。

## 不可变架构规则

1. 同组 source 使用一个有状态 multi-source request；目标侧 connector/route/policy 只做一次，source 通过 merging A* 接入。
2. graph/route/tile 高层工作按真实 operation quota 跨 Tick 执行；quota 只影响完成 Tick，不改变结果或权威数据。
3. request 未完成只能是显式 `PendingNavigation`，不得读旧 handle、方向、目标或同步补完。
4. moving target 同 sector 只更新 local binding；跨 sector 或 dirty topology 仅失效必要 suffix/层级。
5. portal-window tile 身份为 `(world, agent type, sector, exit portal, dirty version)`；exact goal 只属于 final tile，route 只属于 `PathHandle`。
6. `NavigationSync`/`MoveIntent` 不同步全量 hierarchy、portal A* 或 required-tile force commit；UI、准星、镜头等显示交互不进逻辑帧，只有技能施放、移动、建造等命令提交进入 Tick。
7. 核心导航权威使用 `Fix64`/raw。

## 验收门禁

- Play 前强制 Unity `Refresh(all)`、编译并确认 `is_compiling=false`、`is_domain_reload_pending=false`、`ready_for_tools=true`。
- 严格从 Launch 经 procedure 进入 Lv2，运行 `Tools/Logic Frames/Run Lv2 Pull Chase Performance`；记录追击窗口耗时、P99、最大 Tick、pending、hash/Replay 和 Console error。
- 通过 Flow/Replay/Checkpoint/EditMode、容量一致性及功能回归后，且达到 `LogicFrameTick P99 <=8.33ms`、单 Tick `<=16.67ms`、Flow 合计 `P99 <=4ms`、单 Tick `<=8ms`，才允许 Build/收尾。
