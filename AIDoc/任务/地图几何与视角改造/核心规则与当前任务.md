# 地图几何与视角改造：核心规则与当前任务

## 恢复卡片

- 主线：先从生产地形链路移除 TWC、DualGrid 和地块 prefab 选模，再基于项目自有统一几何引入斜角地块，并统一相机、建筑表现、斜坡、碰撞、寻路、Fog、小地图的数据来源。
- 当前阶段：只完成设计记录，尚未修改代码、LDtk、Prefab 或表格。
- 下一步：先完成 TWC 脱链和普通方格占位地形的全模块对接；旧关卡行为验收通过后，再在同一几何链路加入斜角与八方向斜坡。
- 入口门禁：实机始终从 `Launch -> procedure -> EditorRuntimeLevelEntryLauncher.Enter(levelId)` 进入；不能只启动 Play 作为关卡验收。

## 不可变规则

1. `Plane_H0..Plane_H5` 可以重叠，只识别最高层顶面。缺少的下层支撑由导出器自动补齐，不要求 LDtk 重复绘制。
2. 斜坡允许任意 run/rise 组合，只要最终坡度不超过单位可行走角度；连续多级坡允许，不以“长 1 高 2”作为特殊禁例。
3. 斜坡、斜角和平台的真实几何是权威。`0.2` 表示平台暴露边的边框宽度，由统一几何程序化生成；禁止再把它作为某个 prefab 的尺寸补偿或坡体全局外扩参数。
4. 寻路距离、游戏内直线距离均按平面距离；高度只参与可通行和视野遮挡判定。
5. Fog 逻辑格与地块格、FlowGrid 格、表现纹理粒度完全分离。当前 Fog 逻辑粒度仍由配置的 `0.1` 世界单位决定。
6. 高地（不含斜坡）遮挡低地（含斜坡上的低处）单位视野；斜坡高度查询按实际连续高度并按规则向下取整。
7. 核心逻辑使用 `Fix64`；Unity Mesh、Collider、纹理等边界才转换为 `float`。异常数据必须明确报错，不得静默跳过或 fallback。
8. 自动生成的 `.txt/.cs` 不直接修改，必须修改 Excel 或其他来源后重新生成。
9. 本任务不修改 LDtk 打包的 `Tools/LDtk/Custom/renderer.js`，优先使用图块、IntGrid 值和规则完成编辑器预览。
10. 新生产链路不依赖 TWC `Configuration`、`BlueprintLayer`、`BuildLayer`、`TilePreset`、`TileWorldCreatorManager` 或地块 prefab；LDtk 原始格和语义数据直接进入项目自有资产。
11. 平台表现边界、可站边界和遮挡边界允许不同，但必须由同一权威几何按明确规则派生，禁止各模块自行加偏移。

## 目标几何模型

导入器先把 LDtk 转为项目自有的 `TerrainLevelData`，再构建不可变的 `TerrainGeometry`；其余系统只消费这两类资产，不再各自从 TWC 或整格集合重复推导。

`TerrainLevelData` 保存紧凑的关卡语义：地图尺寸、格尺寸、最高平台高度、斜角类型、斜坡组件、水面、据点和实体对齐信息。`TerrainGeometry` 保存由其确定性派生的面、边和高度函数。生成的 Terrain Prefab 只挂项目自有 `TerrainGeometrySource`，不再保留 TWC Manager。

每个几何面至少包含：

- 世界坐标多边形（完整方格或半格三角形）。
- 顶面高度以及可查询的高度函数。
- 面类型：`FullCell`、`CornerCell`、`SlopeSurface`。
- 有序边段、边段高度和连接状态。
- 是否为外边界、平台高差边、斜坡侧边或可连接边。

几何构建顺序固定为：

1. 读取 `Plane_H0..H5`，重叠坐标只保留最高层。
2. 读取 `Corner` 和 `Slope`，将整格占地转换为多边形/楔形面。
3. 推导同高连接边、不同高差边和斜坡侧边。
4. 自动生成从顶面高度向下至 H0 的隐藏支撑体。
5. 输出几何快照供程序化渲染 Mesh、Ground Collider、FlowGrid、Fog、小地图和相机边界使用。

## LDtk 图层和编码

保留：

```text
Plane_H0 .. Plane_H5
Slope
```

新增一个 `Corner` IntGrid 层。默认四个值表示削去的角：

| 值 | 语义 |
|---|---|
| `Cut_NW` | 削去左上角，保留其余三角区域 |
| `Cut_NE` | 削去右上角 |
| `Cut_SE` | 削去右下角 |
| `Cut_SW` | 削去左下角 |

具体整数值放入 LDtk 项目定义和项目自有导入配置，不在运行时代码中散落硬编码。斜角只表达顶面三角区域；其下方支撑和侧壁由几何构建器自动生成。

`Slope` 保留现有 `Auto` 值，并增加八方向显式值：`N/E/S/W/NE/SE/SW/NW`。旧关卡的旧值继续走 `Auto`。当相邻平台高度或方向无法唯一确定时，导入器必须报错并指出格坐标。

## 第一阶段：移除 TWC 与 DualGrid

新链路固定为：

```text
LDtk
  -> TerrainLevelData
  -> TerrainGeometry
      -> TerrainMeshBaker / Collider
      -> FlowGrid Bake
      -> Fog
      -> 小地图
      -> 据点、墙、相机边界和实体定位
```

实施边界：

- 不再生成 `__LDtkDualControl_*` 层，不再调用 `LdtkDualGridControlBuilder`。
- 不再创建或同步 TWC Blueprint/BuildLayer，不再执行 `ExecuteBuildLayers`。
- 不再按 corner/edge/fill/interior/double-corner 选择、旋转或合并地块 prefab。
- 普通平台直接取 LDtk 原始完整格的并集边界；LDtk 画 17 格天然输出 17 格，不再经过控制点重建。
- 初始占位表现为程序化生成的普通立方体/挤出平台，按 chunk 合并为少量 Mesh，不创建每格 GameObject。
- 平台顶面、边框、侧壁、斜角和斜坡最终都由一个 Mesh Baker 生成，避免多个构建器在连接处各自补偿。
- 旧 TWC 包和旧配置在迁移验收期间保留作 A/B 基线，但不进入新生成的 Terrain Prefab；全部关卡通过后再按归档和快照规则清理。

需要从 TWC 迁出的运行时数据：

- `Plane_H*`、`Slope`、`Water` 和地图尺寸迁入 `TerrainLevelData`。
- `SH_*` 据点格迁入关卡 Authoring 数据。
- Fog、Flow Bake、小地图、据点和敌方据点 Fog 改读 `TerrainGeometrySource`。
- 小地图不再订阅 `OnBuildLayersReady`；静态关卡由 `TerrainGeometrySource` 就绪事件或关卡初始化顺序驱动。

## 程序化表现与整体纹理

地块 prefab 只是占位，因此不保留模型规则表。第一阶段先用单一占位材质验证几何和碰撞，后续整体纹理按以下方式接入：

- 顶面使用世界坐标 UV，允许整张地图或每个 chunk 使用统一绘制纹理。
- 侧壁使用沿边累计距离和高度生成连续 UV，避免逐格纹理接缝。
- 可生成材质索引/边框遮罩控制纹理，表达地表类型、平台边框和局部绘制；纹理只是表现产物，不作为逻辑地形权威。
- chunk 只用于渲染裁剪、Mesh 顶点上限和资源增量生成，不得改变 UV 连续性或几何边界。
- 后续若需要装饰物、植被或特殊构件，使用独立装饰层，不重新引入每格地形 prefab。

## 平台边框与边界语义

统一配置 `PlatformBorderWidth=0.2`，只沿同一高度连通平台的暴露外边生成，不沿内部格边生成：

- `SurfaceBoundary`：LDtk 原始完整格/斜角多边形的并集外边，决定可见平台轮廓、小地图和高地遮挡边。
- `WalkableBoundary`：将暴露边向平台内部偏移 `0.2` 后得到，决定 Ground Collider 顶面、Flow 可站区域和单位边缘阻挡。
- `BorderRing`：`SurfaceBoundary` 与 `WalkableBoundary` 之间的可见边框，仅表现，不提供可站区域。
- 平台内部同高连接边不内缩；相邻不同高度的平台各自保留真实高差边，不能直接通行。
- 斜角边使用相同的多边形偏移规则，45°边框宽度与方边一致；偏移导致可站多边形消失时明确报错。
- 斜坡连接边在边框上开连接口。坡面碰撞与 `WalkableBoundary` 连续缝合，坡面表现覆盖连接口和边框过渡，不产生空隙。
- Fog 地形覆盖和高地遮挡读取 `SurfaceBoundary`；单位位置与可行走性读取 `WalkableBoundary`，两者均来自同一几何快照。

## 斜坡生成和连接

每个连续斜坡组件生成一个连续楔形 Mesh，坡面高度为：

```text
h(u) = lowerHeight + rise * u / run,  0 <= u <= run
```

- `run` 使用真实平面长度，对角方向按平面距离计算。
- 支持四方向和四个对角方向。
- 连续同坡面合并生成，避免逐格拼接缝。
- 坡体端部由连接口同时生成表现面和碰撞面；平台外观边界不改动，平台可站边界只在连接口取消内缩。
- 坡面表现覆盖边框过渡，坡面碰撞精确连接平台可站面；不再需要 prefab `ConnectionProfile` 或 `platformEndExtension`。
- 斜角出发的坡使用三角形边界作为底边/顶边，生成裁剪后的楔形。
- 坡度超过配置的单位可行走上限时明确报错或标记不可行走，不改变几何尺寸来掩盖错误。

## 碰撞、悬崖和底层填充

Ground Collider、悬崖侧壁和斜坡侧壁全部由 `TerrainGeometry` 生成，并与渲染 Mesh 分离：

- 平台顶面 Collider 使用 `WalkableBoundary`，渲染顶面和边框使用 `SurfaceBoundary + BorderRing`。
- 初始占位平台按连通区域挤出为普通立方体式体块；不逐格生成 BoxCollider。
- 不同高度平台的公共边生成不可通过的垂直侧壁。
- 斜坡两侧边生成不可横穿的侧壁；上下端连接边可通过。
- 斜角外边生成对应斜边侧壁。
- 顶面向下自动生成 H0 支撑体，隐藏支撑不重复渲染顶面。
- 碰撞 Mesh、边界段和视野遮挡边共享同一顶点/边段数据，禁止各系统单独加偏移。

## FlowGrid 与连续边界方案（保留文献架构）

当前 LvTest Medium FlowGrid 已确认是 `670x530`、`cellSize=0.1`；地块格为 1 世界单位，因此一个地块格约含 `10x10` 个 Flow cell。斜角不需要改成半地块节点、三角节点或 NavMesh，也不能把 FlowGrid 放大回地块粒度。

保留 Chapter 23 的职责边界：sector/portal/hierarchy 决定跨区路线，cost/integration/flow field 决定局部前进方向，连续碰撞负责最终位移和贴墙滑动。文献中的墙体 cushioning、墙边 cost gradient、跨格方向混合和 physics wall slide 分别落在现有 movement-type Bake、source cost、空间梯度插值和静态碰撞层；增加精确斜边线段不改变 flow-field 架构。

### Bake：精确几何进入既有栅格场

1. 每种 movement type 从 `WalkableBoundary` 派生单位中心可行域：外边界按单位半径做精确 Minkowski 内缩，内部双侧阻挡边按半径扩张。不得继续用九点 footprint 近似圆体是否越过斜边。
2. `walkableMask` 仍是一格一个值；cell 中心在可行域内才可走。确需保留边缘 partial cell 时，anchor 取格中心到可行域内的确定性最近点，不使用离散候选点左右跳选。
3. `source cost` 使用 anchor 到真实阻挡边的欧氏净空生成墙边渐变，而不是只到栅格化 blocked cell 的距离。该渐变只写入现有 8-bit cost，不新增运行时 SDF。
4. `neighbor traversal mask` 仍为现有 8 邻居；每条候选邻接在 Bake 时对单位圆做精确线段 sweep。斜向邻接继续要求两条正交侧路成立，禁止切角、跨高差边或横穿斜坡侧边。
5. 斜坡高度只用于坡度和拓扑可通行判定；integration、路径长度和游戏直线距离继续使用平面距离。
6. Bake 使用按 AABB/Flow cell 分桶的边段索引，增加的精确几何工作发生在编辑器，不进入逐 Tick 全图计算。

### 运行时：Flow 指路，精确边界执行

1. 保留现有 cost/integration/flow payload、sector/portal/hierarchy、portal window、cache、分帧 job 和 0.1 粒度。现有 Fix64 势场梯度已在单位位置周围取可通行样本做空间插值，并按 Tick 位移做子步积分；这比只在 8 个离散方向之间瞬切更接近 Chapter 23 的跨格方向混合要求，不为斜角另建 steering 图。
2. `TerrainGeometry` 输出两类固定边段：`BoundaryLoops` 表达可走域的闭合外边界，`BarrierSegments` 表达高差公共边、斜坡侧边等两侧都可能有地面但禁止横穿的双侧阻挡边。相同高度内部边和斜坡上下连接口不输出阻挡边；不得再用所有向上三角形的平面投影 union 猜测这两类语义。
3. 最终水平位移由现有 Fix64 圆体-线段 sweep/slide 求解器裁决，使用真实 45 度法线保留切向分量，因此单位沿斜边连续滑动，不会按 0.1 栅格台阶左右摆动。Flow mask 负责不规划非法路线，精确 solver 负责绝不穿边，两者必须来自同一 `TerrainGeometry`。
4. 当前精确 solver 已在每次受约束移动中作为 shadow 执行，并按 Flow cell 对附近边段分桶；旧 `TryConstrainNavigationDisplacement` 仍用 blocked-cell 扇形、15 度候选和栅格法线产生最终结果。迁移时应先做同帧 A/B 现象和性能记录，再让精确结果成为唯一静态地形位移权威并删除旧扇形裁决，不能长期保留两套结果。
5. `BoundaryLoops`、`BarrierSegments`、稳定段 ID 和分桶结果属于导航 fixed authority；新增序列化字段必须进入版本校验、world hash、checkpoint/replay 和确定性测试，不能只存在于 Unity Collider shadow。
6. 第一版不增加运行时 SDF/clearance-normal 场，也不逐单位遍历完整多边形。只有实机证明“精确墙边 cost + 插值势场 + 精确 slide”仍出现持续压墙或摆动时，才用现象数据评估紧凑法线场。

性能预期不是无条件结论，必须用现有门禁实测：Flow 数组和 tile 构建规模不变；静态边段数据量随合并后的平台轮廓和阻挡缝增长，不随地图面积逐格增加；每次碰撞只查位移扫过的局部分桶，且该 solver 当前已经作为 shadow 支付成本。提升其为权威并移除旧栅格候选链，目标是运行时不增反降，但仍需以 `LogicFrameTick P99 <= 8.33ms`、Flow 合计 `P99 <= 4ms`、单 Tick Flow `<= 8ms` 验收。

## Fog 方案

`Fog3TerrainDetector` 从 `TerrainGeometrySource` 生成现有 Fog 地图数组，不再查找 TWC Manager 或读取 `platformEndExtension`：

- Fog 逻辑格按配置的 `0.1` 世界单位独立栅格化。
- 通过多边形覆盖/中心高度查询决定逻辑格是否有地形及其高度。
- 斜角只覆盖三角区域，三角外不产生平台视野。
- 斜坡每个逻辑格使用连续高度，平台高度按向下取整规则参与可见性。
- 高差边、斜角边和斜坡侧边进入离散遮挡边集合。
- 权威 Fog 状态立即生效；渐变仅属于表现层，不能改变逻辑可见性。
- 表现纹理采样、羽化和逻辑粒度继续分离，不以地块格尺寸替代 Fog 粒度。

## 小地图方案

`MinimapTerrainMapBuilder` 改为从 `TerrainGeometrySource` 的 `SurfaceBoundary` 栅格化：

- 完整平台填充方形。
- 斜角填充三角形，不把整格涂满。
- 斜坡按顶面投影填充，高度颜色取实际顶面高度。
- 世界边界和相机框继续共用同一几何 AABB/坐标变换。
- 相机 Yaw 改为 0 后重新核对小地图方向，但不通过缩放补偿坐标误差。

## 相机、建筑和实体

相机表源文件 `AAAGameData/DataTables/CameraViewTable.xlsx` 的默认视角改为：

```text
X=35, Y=0, Z=0
```

所有相机投影、屏幕边缘平移、地面投影和 Fog 覆盖计算继续读取该配置，禁止残留硬编码 45 度。

建筑保持原有实机等距表现：

```text
最终建筑显示 Yaw = LDtk 实体 Yaw + 45°
```

该偏移作用于建筑表现根节点，并带动渲染、碰撞、阻挡、阴影和选中框；地形逻辑坐标、Flow、Fog 不随建筑表现旋转。

LDtk 实体增加 `Yaw` 自定义字段，默认 0。LDtk 内的几何预览使用图块和规则完成：

- `Corner` IntGrid 四个值绑定四张方向图块。
- `Slope` 的 Auto/八方向值绑定方向图块，规则显示连接端和侧边。
- 建筑占地使用现有实体矩形/图块预览；需要离散旋转时使用预旋转图块或平行预览图层，不修改 `renderer.js`。
- 导入器只把实体字段作为语义输入，最终模型旋转在 Unity 导入阶段统一应用。

## 实现阶段

1. TWC 脱链：建立 `TerrainLevelData`、`TerrainGeometry`、`TerrainGeometrySource` 和直接 LDtk 导入；用程序化普通体块输出旧关卡平台、边框、侧壁和 Collider。
2. 全模块迁移：Flow Bake、Fog、小地图、据点、敌方据点 Fog、墙和相机边界改读新资产；保持 Flow 场、sector/portal/hierarchy 和性能契约不变，同时把精确外边界/双侧阻挡边接入现有静态碰撞数据。
3. 旧关卡 A/B 门禁：对比 TWC 基线的占地尺寸、最高层、碰撞、Flow mask/anchor/neighbor、Fog 高度、据点和小地图；通过后从生产 Prefab 移除 TWC Manager。
4. 增加 `Corner` 层解析、四种三角形、统一边框偏移和方格/斜角连接；Bake 使用精确单位中心可行域、真实墙距 cost 和圆体邻接 sweep。
5. 生成连续任意 run/rise 楔形，支持八方向、斜角连接、多级坡和边框连接口。
6. 接入整体纹理 UV、边框遮罩和最终地表材质；占位几何阶段不得阻塞逻辑验收。
7. 修改 CameraViewTable 源 Excel、建筑 45°显示偏移和 LDtk `Yaw` 字段。
8. 配置 LDtk 图块、IntGrid 值和规则预览，补齐导入错误提示。
9. 对精确静态 solver 与旧栅格扇形位移链做同帧 A/B；斜边贴边、内部高差边和斜坡侧边通过后，以精确 solver 作为唯一静态地形位移权威并移除旧扇形裁决。
10. 完成静态测试、导出回归、Prefab/Collider/Flow/Fog/小地图检查，再走 Launch 链路实机截图和性能验收；最终按快照/归档规则清理旧 TWC 生产资产。

## 验收门禁

- 新生成 Terrain Prefab 不包含 TWC Manager、TWC Configuration、Blueprint/BuildLayer 或地块 prefab 实例。
- LDtk 平台格直接一格对一格进入几何；17 格输入保持 17 格外观边界，空 Corner 层不改变旧关卡占地。
- `0.2` 只沿平台暴露边形成统一边框和可站区内缩；内部格边无碰撞缝，斜坡连接口连续。
- 旧关卡的 FlowGrid 运行时契约不变；无意图变化时 walkable、anchor、neighbor mask 和 authority 数据与基线一致。
- 四种斜角可无缝组成八边形，方格/斜角/斜坡连接无可见缝。
- 斜坡上下端不穿透，侧边和不同高度平台边不可越过。
- 任意 run/rise 只按实际坡度判定可行走；连续多级坡可通行。
- Flow 场、sector/portal/hierarchy、查询接口和预算不因斜角改变；Bake 后斜角单位中心可行域、真实墙距 cost、anchor 和邻接均可重复且正确。
- 单位以多个入射角连续贴行 45 度边时，无 0.1 格台阶摆动、15 度扇形折线、穿边或无故停步；外轮廓、高差公共边和斜坡侧边均由精确线段约束，连接口不误封。
- 精确静态 solver 成为权威后，运行时不存在另一个会给出不同结果的栅格静态地形裁决；完整 Flow 性能门禁不得回退。
- Fog 不覆盖三角形外区域；高地遮挡低地和斜坡下方；静止和过渡表现均无块状错位。
- 小地图轮廓、方向和高度颜色与实机一致。
- 固定相机位置截图中，LDtk 方向、实机地形和建筑表现一致。
- Console 无新增 error；异常 LDtk 数据必须显示坐标和原因。
