# 地图几何与视角改造：历史记录

本文件记录本任务的方案演进、被撤销的设想和验证证据。当前规则以同目录的 `核心规则与当前任务.md` 为准；本文件不维护 NOW/NEXT。

## 2026-08-29 初始方案纠偏

用户要求先完成地图与视角大改的完整方案，再实施。目标包括：相机 Yaw 从 45° 改为 0°、建筑增加 45°显示旋转、新增斜角地块、兼容 DualGrid/斜坡/碰撞/Flow/Fog/小地图，并改善 LDtk 编辑预览。

本轮确认并记录以下修正：

1. “LDtk 画 17 格、导出 18 格”是旧问题，已经通过算法修复。本任务不得把它重新当作根因或回退 DualGrid；只需验证斜角接入不会破坏现有修复。
2. FlowGrid 正处于性能调优阶段。原先提出“改为半地块运行图”的方向撤销，避免扩大与文献的数据结构差异和运行时优化难度。当前方案只在编辑器 Bake 阶段用真实几何采样，保持现有 FlowGrid 分辨率、接口、sector/portal/hierarchy、分帧预算和运行时数组。
3. 原先提出的外部 LDtk 几何预览工具撤销。编辑器预览改用 `Corner`/`Slope` IntGrid 图块、自动层规则和实体/平行预览图块完成，不修改打包 `renderer.js`。
4. 固定 `platformEndExtension=0.2` 作为坡体连接补偿的方向撤销。坡体应由真实平台边界和连接 profile 决定，平台本身不能外扩。
5. 斜坡不限制为 45°或单级高差；统一生成任意 run/rise 的连续楔形，只按单位最大可行走坡度判定。

## 2026-08-29 决定移除 TWC 生产链路

用户确认现有地块 prefab 只是占位，不需要保留 prefab 选模和 DualGrid 链路；平台可以先使用普通立方体式程序化占位，后续统一绘制整体纹理。该决定覆盖初始方案中“保留 TWC/DualGrid 并适配斜角”的方向。

只读审计确认 TWC 当前实际承担：保存 Blueprint 格数据、DualGrid 五类规则和旋转、Top/Middle prefab 选择、多层实例化、按 cluster 合并 Mesh、生成 MeshCollider，以及为 Fog、小地图、Flow Bake 和据点提供运行时数据。TWC 的 modifier、mask、override、加权随机和运行时地图重建在当前生产关卡中没有形成必要能力。

当前方案改为：

1. 先建立项目自有 `TerrainLevelData -> TerrainGeometry -> TerrainGeometrySource`，把 TWC 从数据权威和生产 Prefab 中移除。
2. 平台、边框、侧壁、斜角和斜坡统一由程序化 Mesh/Collider Baker 生成；第一阶段使用普通体块占位材质，后续使用世界坐标 UV、整体纹理和边框遮罩。
3. 原模型约 `0.2` 内缩重新定义为平台暴露边框宽度：外观/遮挡使用原始平台边界，碰撞和 Flow 可站区域使用向内偏移 `0.2` 的边界，斜坡连接口取消该段内缩并连续缝合。
4. Flow 只更换编辑器 Bake 数据源，运行时网格、sector/portal/hierarchy、预算和性能优化架构不变。
5. TWC 包在 A/B 验收期间只作为旧基线保留；完成全部关卡迁移后再按快照和 `Archive` 规则清理，不能直接删除。

## 2026-08-29 斜角 Flow 与连续边界方案纠偏

用户澄清允许调整 Flow 周边结构，目标是在不偏离 Chapter 23 且不损害性能的前提下，让单位沿斜角视觉边界自然移动。只读核实得到以下证据：

1. LvTest Medium FlowGrid 为 `670x530`、`cellSize=0.1`，不是地块格粒度；一个 1 世界单位地块已有约 `10x10` 个 Flow cell。此前担心斜角必须退化成半地块图或粗台阶没有事实基础。
2. Chapter 23 明确把墙和几何坡度烘入 cost field，建议墙边 cost gradient、大单位 wall cushioning、跨格混合 flow direction，并由 physics 处理贴墙滑动。连续斜边碰撞属于该 steering/physics 分层，不是把算法改成文献外的多边形寻路。
3. 当前运行时已从 integration field 计算 Fix64 空间插值梯度并对子步位移积分，不是简单每格取一个 8 向量。当前 Bake 也已有 movement-type footprint、anchor、source cost 和 8 邻居 mask。
4. 当前 `DeterministicStaticCollision` 已保存 Fix64 边界线段、按 Flow cell 建局部分桶，并支持圆体对任意线段的 sweep、接触法线和切向 slide。它已在每次受约束移动中作为 shadow 求解；但最终 `TryConstrainNavigationDisplacement` 仍使用 blocked-cell 法线、15 度扇形候选和前缀二分。两套几何权威不一致才是斜边可能出现折线、摆动或视觉不贴边的结构风险。
5. 当前 Ground 顶面三角形投影 union 只能稳定表达闭合外轮廓；高差公共边和斜坡侧边可能在两侧投影都有地面，必须由新 `TerrainGeometry` 显式输出双侧阻挡边，不能指望投影 union 自动保留。正式数据需区分闭合 `BoundaryLoops` 和双侧 `BarrierSegments`，并纳入 fixed authority、world hash 与 replay 版本。

因此撤销“斜角只改 Bake、运行时任何结构都绝不调整”的过度约束。当前方案保留 cost/integration/flow、sector/portal/hierarchy、portal window、cache、0.1 粒度和分帧预算；Bake 改为精确单位中心可行域、真实边距 cost 和圆体邻接 sweep；运行时将现有精确 solver 从 shadow 提升为唯一静态地形位移权威并移除旧栅格扇形链。第一版不增加 SDF 或逐帧多边形遍历，性能按既有门禁实测。
