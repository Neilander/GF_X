# 敌军资源等价量成长与防御出兵系统

## 1. 文档目的

本文冻结敌军资源等价量成长、防御阶段出兵和据点守军的目标方案，作为数据迁移、运行时实现、编辑器改造和测试验收的唯一清单，避免在后续修改中退回旧的“每天手配数量与等级”方案。

本文不再使用“强度”或裸的“价值”命名这一数据。稳定的领域名是“资源等价量（ResourceEquivalent）”：它表示按军事建筑资源投入推导、用于将一个敌方小队换算为数量与等级构成的标尺。当前表和编辑器以橙髓为显示单位，但代码不绑定具体货币名；未来更换资源名称不需要修改领域 API。

## 2. 已确定的设计目标

### 2.1 关卡内敌军成长

- 进攻阶段的 LDtk 据点守军随当前天数成长。
- 防御阶段的敌方出兵随当前天数成长。
- 守军的成长速度低于防御出怪，二者不能使用同一条成长曲线。
- 两者共用各等级单兵资源等价量和小队构成求解算法。
- 每关只配置预期天数，不逐日配置目标资源等价量。
- 预期天数是每日成长增量的峰值日；超过预期天数后每日增量快速下降，避免长期局继续高速膨胀。
- 初始资源等价量和成长速度都可被开局 Tag 等运行时效果修改。
- 路线、出兵时间和小队启用波次保持可重复；当前据点、建筑或单位状态不能改变防御路线。

### 2.2 作者输入保持精简

每个单兵种小队只要求作者填写：

- 单位类型。
- 初始资源等价量 `InitialResourceEquivalent`，当前以橙髓计。
- 数量成长权重 `CountGrowthWeight`，范围 0 到 1。

`CountGrowthWeight=1` 偏向增加低等级单位数量，`CountGrowthWeight=0` 偏向减少数量并提高等级。算法最多生成两个相邻等级段，不允许作者逐日手配数量和等级。

### 2.3 单兵种模板

- 一个 LDtk Soldier 点只表示一个兵种。
- 一个防御小队模板只表示一个兵种。
- 同一路线可以配置多个不同兵种的小队模板。
- 防御小队模板直接参与运行时出怪，不生成按天的 `D几` 数据实例。
- 编辑器中不展示按天实例名；模板 ID 由路线名和可空后缀派生，只有后缀可编辑。传送点序列内部使用 `_`，后缀统一使用 `@` 连接，例如 `2_1_0@Left`，避免数字后缀被误认为途经传送点。

## 3. 资源等价量标尺

### 3.1 军事建筑推导各等级单兵资源等价量

从 `BuildingTable` 中找到 `Type=Army` 且 `UnitID` 对应目标兵种的军事建筑。

定义：

```text
P1 = Lv1Production
P2 = Lv2Production > 0 ? Lv2Production : P1
P3 = Lv3Production > 0 ? Lv3Production : P2

C1 = Lv1Cost
C2 = Lv1Cost + Lv2Cost
C3 = Lv1Cost + Lv2Cost + Lv3Cost

I1 = C1 / P1
I2 = C2 / P2
I3 = C3 / P3
```

`I1/I2/I3` 是每名兵的原始累计投入值，单位为橙髓。

由于高级军事建筑的性价比低于一级建筑，原始投入不能全部视为等量的有效资源等价量。最终供构成算法使用的各等级单兵资源等价量为：

```text
V1 = I1
V2 = I2 * EnemyUnitLevel2ResourceEquivalentScale
V3 = I3 * EnemyUnitLevel3ResourceEquivalentScale
```

折减系数放在 `GameConfig`，初始建议值：

```text
EnemyUnitLevel2ResourceEquivalentScale = 0.80
EnemyUnitLevel3ResourceEquivalentScale = 0.70
```

这两个值必须大于 0 且不大于 1。折减后必须满足 `V1 < V2 < V3`；不满足时明确报错，不能排序、钳制或回退到原始投入值。

`I1/I2/I3` 只是算法内部中间值，不在编辑器显示。编辑器只展示最终参与构成求解的 `V1/V2/V3`，让作者直接判断各等级兵的单兵资源等价量是否合适。

### 3.2 数量不参与额外倍率

玩家与敌方单位数量都会随流程从少到多，因此敌军成长不再额外模拟少量协同或大量拥堵。数量只作为线性乘数参与资源等价量计算，不存在 `Q(n)`、数量拐点、协同系数、拥堵系数或按近战/远程/体型分类的数量曲线。

### 3.3 小队组合资源等价量

设 `Nl` 为等级 `l` 的人数，`Vl` 为该等级单兵资源等价量：

```text
SquadResourceEquivalent = Σ(Vl * Nl)
```

纯单等级小队为：

```text
SquadResourceEquivalent = UnitResourceEquivalent[level] * Count
```

增加任意等级的一个单位，组合资源等价量都严格增加该等级的单兵资源等价量。数量本身不产生协同放大或拥堵折损，混合等级也不会稀释已有高级兵。

LDtk 和防御表中的初始资源等价量都使用这一标尺。现有已迁移数值不再次机械改写，只按新线性公式解释并求解后续编成。

## 4. 天数成长曲线

### 4.1 曲线形状

Day 1 是初始资源等价量的基准点，倍率为运行时初始量修正 `InitialResourceEquivalentScale`。成长按每日增量累计：

```text
DailyIncrementPerDay1BaseResourceEquivalent = Day2IncrementPerDay1BaseResourceEquivalent
Growth = 0

for CurrentDay = 2 .. Day:
    if CurrentDay <= ExpectedDays:
        Growth += DailyIncrementPerDay1BaseResourceEquivalent
        if CurrentDay < ExpectedDays:
            DailyIncrementPerDay1BaseResourceEquivalent += PreExpectedDailyIncrementIncreasePerDay1BaseResourceEquivalent
    else:
        DailyIncrementPerDay1BaseResourceEquivalent *= PostExpectedDailyIncrementMultiplier
        Growth += DailyIncrementPerDay1BaseResourceEquivalent

Multiplier = InitialResourceEquivalentScale * (1 + Growth * ResourceEquivalentGrowthSpeedScale)
TargetResourceEquivalent = InitialResourceEquivalent * Multiplier
```

三个参数都直接表达现象，并明确所有每日增量的基准始终是 Day 1 初始资源等价量，不是前一日总量：

- `Day2IncrementPerDay1BaseResourceEquivalent`：Day 1 到 Day 2 新增量占 Day 1 初始资源等价量的比例。
- `PreExpectedDailyIncrementIncreasePerDay1BaseResourceEquivalent`：预期天数前，下一日增量固定再增加多少 Day 1 初始资源等价量；例如 `0.008` 表示下一日新增量比上一日多 Day 1 初始量的 `0.8%`。
- `PostExpectedDailyIncrementMultiplier`：越过预期天数后，下一日增量乘以前一日增量的倍率，范围 `(0,1)`。

因此第 `d` 日目标量始终是 `Day1BaseResourceEquivalent * (1 + 累计增量比例)`。设 `t=d-1`，在 `d<=ExpectedDays` 时，累计成长比例为 `Day2Increment*t + PreExpectedIncrementIncrease*t*(t-1)/2`，是关于天数的二次函数。它不是复利，也不再包含预期日前的指数项。`ResourceEquivalentGrowthSpeedScale` 只缩放累计增量比例，不改变 Day 1 基础量。

性质：

- Day 1 不受成长速度修正影响，保证初始资源等价量修正和成长速度修正职责分离。
- 对任意两个关卡，只要都尚未到各自预期天数，同一 Day 的基础成长完全相同，不因 `ExpectedDays` 改写前半段。
- 预期天数越长，线性增加每日增量的阶段持续越久；到达预期天数时的累计成长按二次曲线提高。
- 预期天数是每日增量由加速转为衰减的位置；之后仍增长，但每日增量快速下降，形成先加速、后放缓的 S 型累计曲线。

### 4.2 守军与出怪使用不同曲线

共享公式，但配置分离：

```text
EnemyGarrisonDay2IncrementPerDay1BaseResourceEquivalent
EnemyGarrisonPreExpectedDailyIncrementIncreasePerDay1BaseResourceEquivalent
EnemyGarrisonPostExpectedDailyIncrementMultiplier

EnemyDefenseDay2IncrementPerDay1BaseResourceEquivalent
EnemyDefensePreExpectedDailyIncrementIncreasePerDay1BaseResourceEquivalent
EnemyDefensePostExpectedDailyIncrementMultiplier
```

约束：

- 守军的主要增长速度必须低于防御出怪。
- 编辑器按同一 `ExpectedDays` 同图展示两条倍率曲线。
- 自动校验 Day 2 到 `ExpectedDays * 2` 范围内，守军倍率不能达到或超过防御出怪倍率。
- 当前表值：守军 `0.2 / 0.2 / 0.3`，防御出怪 `0.6 / 0.6 / 0.4`，依次表示 Day 2 增量占 Day 1 基础资源等价量的比例、预期日前每日增量固定增加量、预期日后每日增量倍率。

不使用“先算同一曲线再临时乘守军倍率”的实现，因为那会把初始差异、斜率差异和后期收敛混在一起，且无法独立预览和验证。

### 4.3 运行时效果接口

运行时效果按上下文提供：

```text
EnemySquadResourceEquivalentContext.Garrison
EnemySquadResourceEquivalentContext.DefenseWave

GetEnemyInitialResourceEquivalentScale(context)
GetEnemyResourceEquivalentGrowthSpeedScale(context)
```

现有 `LvTag_OverwhelmingForceI/II` 从“直接增加最终数量”迁移为初始资源等价量倍率，避免在求解后再次修改人数。未来成长速度 Tag 通过同一接口返回倍率。

旧 `ModifyEnemySpawnCount` 必须删除全部调用，防止价值成长和数量成长叠加。

## 5. 给定资源等价量求解小队构成

输入：

```text
InitialResourceEquivalent
CountGrowthWeight
Day
ExpectedDays
InitialResourceEquivalentScale
ResourceEquivalentGrowthSpeedScale
V1/V2/V3
对应上下文的成长曲线配置
MaximumResolvedUnitCount
```

步骤：

1. 计算当天 `TargetResourceEquivalent`。
2. 由最高等级单兵资源等价量反推允许的最少人数并向上取整；由一级单兵资源等价量反推允许的最多人数并向下取整。
3. 使用 `CountGrowthWeight` 在最少、最多人数之间插值并取最近整数。
4. 用 `TargetResourceEquivalent / TotalCount` 得到目标平均单兵资源等价量，定位两个相邻等级。
5. 按鸡兔同笼方程直接求高等级人数：`HighCount=(Target-LowValue*TotalCount)/(HighValue-LowValue)`，取最近整数，其余为低等级人数。
6. 固定使用最近整数和相同的舍入规则，保证确定性。

结果最多包含两个相邻等级段，例如 `Lv1 x 8 + Lv2 x 2`。不枚举所有数量与等级组合。

若目标资源等价量低于一名一级单位、等级资源等价量不严格递增、输入权重越界或人数超出明确上限，运行时直接报错，不静默跳过或 fallback。

## 6. 数据模型

### 6.1 LevelTable

新增：

```text
ExpectedDays int
```

每关填写预期通关天数。它控制该关成长曲线拐点和总成长幅度，不逐日填写目标资源等价量。

### 6.2 LDtk Soldier 据点守军

字段：

```text
Identifier string                  单位类型，不包含按天派生等级
ResourceEquivalent float           初始小队资源等价量，当前以橙髓计，必须大于 0
CountGrowthWeight float            数量成长权重，范围 0..1
```

删除旧 `Count` 语义。Importer 必须严格读取 `ResourceEquivalent` 和 `CountGrowthWeight`，转换为 `Fix64` raw 序列化到 `EntityPresetPoint`；字段缺失、非有限数、非正资源等价量或权重越界均明确报错。

`EntityPresetPoint` 不直接序列化 `Fix64` 对象，保存：

```text
unitResourceEquivalentRaw long
unitCountGrowthWeightRaw long
```

并通过属性和严格 setter 暴露 `Fix64`。

### 6.3 DefendAttackGroupTable 防御小队模板

目标列：

```text
Identifier
LevelIdentifier
ActiveDefenseWaves int[]
RouteIdentifier
UnitIdentifier
InitialResourceEquivalent Fix64
CountGrowthWeight Fix64
RelativeLeaderEngagementSeconds Fix64[]
Suffix
```

关键语义：

- `InitialResourceEquivalent` 是初始小队资源等价量，当前以橙髓计，替代旧数量。
- `ActiveDefenseWaves` 是模板在哪些“第 N 次防御”中显式启用，不直接存真实 Day，也不创建每日实例。
- `RelativeLeaderEngagementSeconds` 与 `ActiveDefenseWaves` 等长且按索引一一对应，允许为 `0`，表示作者配置的队首相对接战时间。每波开始前会统一平移为可执行的绝对接战时间。
- 防御波次到真实 Day 的映射由 `LevelTable.StartPhase` 和真实阶段推进规则统一计算；成长使用真实 Day，编排选择使用防御波次。
- 若某个防御波没有任何显式配置，则完整沿用最近一个更早波次的模板集合与相对接战时间；只有资源等价量按当前真实 Day 继续成长。第一波没有可继承编排时明确报错。
- `UnitIdentifier` 是单一兵种，不含等级。
- 路线已在模板内，不重复配置路线信息。
- `Identifier` 由 `RouteIdentifier + @ + 可空 Suffix` 派生；后缀为空时不添加 `@`，同关卡不可重复。

## 7. 运行时链路

### 7.1 进攻阶段据点守军

`PhaseManager.ConfigureInvadeSpawnPoints` 保存：

```text
Position
UnitType
AuthoredResourceEquivalent
CountGrowthWeight
Name
```

不再保存作者配置的单位等级和数量。

进入进攻阶段生成守军时：

1. 读取当前真实天数。
2. 读取当前关卡 `ExpectedDays`。
3. 从军事建筑推导该兵种 `I1/I2/I3` 和折减后的 `V1/V2/V3`。
4. 读取守军成长曲线、最大求解人数和 Tag 修正。
5. 求解为一个或两个等级段。
6. 每个等级段分别生成确定性的 `InvadeSpawnPlan`。
7. 玩家已占领据点仍按既有逻辑不生成守军；据点归属不会改变其他据点的资源等价量或路线。

### 7.2 防御阶段出怪

防御阶段先由当前真实 Day 与 `StartPhase` 求第几次防御，再查找不晚于该波的最近显式编排。模板集合和相对接战时间来自该来源波，资源等价量仍按当前真实 Day 计算。

每个启用模板：

1. 使用防御出怪曲线计算当天目标资源等价量。
2. 求解该单兵种模板的等级与数量构成。
3. 读取来源波对应的队首相对接战秒数。全波统一计算 `Shift=max(0, max(预计距离上限/最高估算移速-相对接战时间))`，每队绝对接战时间为 `相对接战时间+Shift`，保持作者配置的小队间相对节奏不变。
4. 根据绝对接战时间、预计距离上下限和估算移速范围推导每队队首合法出兵窗口。调度器只选择队首时刻；同队第 `i` 只单位严格在 `LeaderSpawnTime + i * SameGroupSpawnIntervalSeconds` 出兵。调度目标是在合法窗口内尽量增大全波任意两只敌人的出兵时间间距，不能改变同队固定间隔。
5. 排程完成后，根据关卡内首个玩家占领的路线据点计算队首为准的临时移速；同一小队所有单位使用完全相同的临时移速，后续成员不要求与队首同时抵达。
6. 单位进入该首个玩家据点的既有视野触发范围后恢复正常移速。

出兵时间由模板资源等价量求出的单位数、来源波相对接战时间、固定路线和同队固定间隔唯一确定，不读取据点归属、建筑、单位或视野状态。关卡内据点归属只影响整队临时移速以及对应来源是否被占领停用；在目标资源等价量和配置不变时，既定出兵时刻不变。生成单位时只消费已经求解好的计划，不实时重复计算路径和资源等价量。旧的“全波最小出兵间隔”已删除；跨小队不存在硬性最小间隔，只由队首窗口调度目标尽量错开全波每只敌人的实际出兵时刻。

防御阶段开始前必须完成流场距离预热和出怪计划构建，预热未完成不能出怪。

## 8. 防御配置编辑器

入口保持在 Unity 顶层菜单：

```text
Tools/Defense Route Editor
```

### 8.1 编辑方式

- 顶部选择关卡和防御波次。编辑器读取 `StartPhase`，下拉项显示“第 N 次防御（Day D）”，不允许选择不会发生防御的日期；最大显示到预期日之后的第一次防御。
- 路线编辑继续按稳定的传送点 ID 记录与预览。
- 出兵组页展示当前关卡所有可复用模板。
- 每个模板在当前波次提供“本波启用”勾选框，直接维护 `ActiveDefenseWaves`；勾选后同时编辑该波队首相对接战秒数。
- 当前波没有显式配置时，列表展示最近上一波的完整继承结果及来源波。第一次修改会先把完整继承编排实体化到当前波，再应用本次勾选或时间修改，避免只修改一个模板就意外丢失其他继承模板。
- 编辑态模板列表保持表内/创建顺序稳定；启用状态变化不得触发即时重排，也不得改变当前选中的模板。保存时才对写表副本排序。
- 不展示或生成 `D几` 实例。
- 仅编辑模板后缀，ID 自动由路线名和后缀刷新。
- 新建小队的初始资源等价量直接取所选兵种一级单兵资源等价量，不设置独立的编辑器默认值。
- 不再配置“接在哪一队后面”或额外开始延迟；波内错峰由每波队首相对接战时间、全波统一平移和同队固定间隔求解。

### 8.2 单模板预览

每个模板显示：

- 初始资源等价量与当天目标资源等价量，当前单位均为橙髓。
- 折减后的各等级单兵资源等价量 `V1/V2/V3`。军事建筑累计成本/兵力只作为内部推导步骤，不显示 `I1/I2/I3`。
- 当天成长倍率及 Tag 修正后的倍率。
- 求解结果，例如 `Lv1 x N + Lv2 x M`。
- 实际组合资源等价量、目标资源等价量和离散误差。
- 总人数和平均等级。

### 8.3 曲线与合理性判断

展示 Day 1 到 `ExpectedDays * 2`：

- 守军倍率曲线。
- 防御出怪倍率曲线。
- 曲线必须有 Day 横轴、资源等价量倍率纵轴、刻度、网格和具体倍率值，不能只显示无量纲折线。
- 明确显示线性编成公式：`小队资源等价量 = Σ(各等级单兵资源等价量 × 对应数量)`，数量本身不产生额外倍率。
- 当前模板每个防御波的显式/继承状态、真实 Day、队首相对接战时间、目标资源等价量、总人数和平均等级。
- 每个防御日的来源编排波、小队数和全波目标资源等价量（橙髓）。

自动给出现象级提示：

- 两条曲线的每日增量是否都在预期天数达到峰值，并在之后衰减。
- 预期天数后边际增长是否明显下降。
- 守军曲线是否始终慢于防御出怪曲线。
- 离散组合资源等价量与目标资源等价量误差是否过大。
- 预期天数内是否出现异常高等级或异常数量。
- 作者期望的怪海模板在短关卡内是否过早升到三级。
- 精英模板在预期天数内是否过早增长到过多单位。

编辑器预览与运行时必须调用同一个 `Fix64` 求解器，不能另写近似公式。

## 10. 确定性与性能要求

- 核心成长、价值、构成和排程均使用 `Fix64`。
- 同一关卡、天数、Tag 和表数据必须得到完全相同的构成、路线与出兵时间；据点归属只允许改变整队临时移速和出兵来源是否停用，不能反向改变排程。
- 不根据玩家当前建筑、单位视野或临时单位位置改变防御路线。
- 据点占领可按既有规则减少对应守军或出兵来源，这是可重复策略的一部分。
- 小队构成在阶段准备时一次性求解；单位生成时不重复推导。
- 路径距离使用现有流场距离预热链路；预热完成事件驱动出兵准备，不每帧轮询路径。

## 11. 错误处理

以下情况必须明确报错并阻止错误计划运行：

- 军事建筑或兵种映射不存在。
- 军事建筑成本、兵力无效。
- 高级兵折减后单兵资源等价量不严格递增。
- `ExpectedDays <= 0`。
- 初始资源等价量非正。
- 数量权重不在 0 到 1。
- LDtk 新字段缺失或仍使用旧 `Count`。
- `ActiveDefenseWaves` 与 `RelativeLeaderEngagementSeconds` 长度不一致、波次重复、相对接战时间为负或超过允许编辑波次。
- 当前防御波没有显式编排且不存在更早编排可继承。
- 目标资源等价量不足以生成一名一级单位。
- 固定出兵窗口、路线或预热结果无效。

不通过静默跳过、默认值或 fallback 隐藏配置错误。

## 13. 验收标准

1. 同一 Soldier 或防御模板只需配置兵种、初始资源等价量和数量权重，即可在不同天得到确定性构成。
2. 同一天相同初始资源等价量下，守军成长倍率低于防御出怪倍率。
3. Day 1 调整成长速度不改变初始资源等价量；调整初始量立即改变 Day 1 目标量。
4. 高等级兵单兵资源等价量由对应军事建筑推导，且折减系数实际影响最终构成。
5. 怪海权重产生更多、更低等级单位；精英权重产生更少、更高等级单位。
6. 小队资源等价量严格等于各等级单兵资源等价量乘对应数量后求和，数量不产生额外倍率。
7. 向任意已有编成增加任意等级单位，组合资源等价量精确增加该等级单兵资源等价量；低级兵不能稀释高级兵的已有量。
8. 不同预期天数的关卡在共同的预期日前具有完全相同的二次基础成长；预期更长只会延长每日增量线性增加的阶段，并在更晚的预期日达到更高峰值。
9. 防御编辑器能在保存前看见两条曲线、线性换算公式、每日构成和误差，并能直接判断参数是否导致过早三级或数量失控。
10. 每个显式防御波都有独立的队首相对接战时间；缺省波完整沿用上一波编排，不再配置前置小队或额外延迟。
11. 相对接战时间允许为 0；不足时只做全波统一平移。全波排程只操作队首，同队成员严格保持表定间隔并使用队首反推的同一临时移速；目标资源等价量与配置不变时，据点归属、建筑和单位状态不能改变出兵时刻。
12. 流场预热未完成时不会提前出怪；预热完成后生成链路无明显阶段切换卡顿。
13. 所有异常数据产生带关卡、模板或 Soldier 标识的明确错误，不静默降级。
