问题 三个入口，三套逻辑

目前有三个地方都在做"创建单位"这件事：

  • BuffTestProcedure.ShowSoldier — 实例方法，创建单个单位
  • BuffTestProcedure.SpawnSoldier — 静态方法，批量创建
  • SoldierFactory.ShowSoldier — 工厂方法，没人调

Buff 添加也分散在两处：

  • SoldierFactory.AddInitialBuffs（死代码）
  • OnShowEntitySuccess 的 switch-case（实际生效）

核心矛盾：SoldierFactory 想同步拿到实体后立即加 Buff，但 GF 的 ShowEntity 是异步的。

SoldierFactory.cs Assets/AAAGame/Scripts/Entity/
① SoldierFactory.ShowSoldier — 创建单位入口（死代码）
public static SoldierEntity ShowSoldier(
    string index, Vector3 position,
    SideType side, BrainType brainType)
{
    EntityParams paramsData = EntityParams.Create(position: position);
    paramsData.Side = side;
    paramsData.BrainType = brainType;
    paramsData.Index = index;

    string prefabName = GetSoldierPrefabName(index);

    int entityId = GF.Entity.ShowEntity<SoldierEntity>(
        prefabName, Const.EntityGroup.Level, paramsData);

    Entity entityObj = GF.Entity.GetEntity(entityId);
    SoldierEntity entity = entityObj?.gameObject.GetComponent<SoldierEntity>();

    if (entity == null)
    {
        GF.LogError($"SoldierFactory: 创建单位失败，index={index}");
        return null;
    }

    AddInitialBuffs(entity, index);

    return entity;
}

Bug 同步拿异步结果

绿线 ShowEntity 发起异步创建请求，返回 entityId。

红线 紧接着 GetEntity(entityId)，但实体在同一帧内还未创建完成，所以 entityObj 必定为 null。

结果：走到 entity == null 直接 return，AddInitialBuffs 永远不会执行。

这个方法目前也没有任何调用者，是死代码。

重复 与 OnShowEntitySuccess 中的逻辑完全相同

根据 index 给单位添加对应的 Buff，逻辑本身没问题。

但这段代码因为上面的异步 bug 永远走不到，实际生效的是 OnShowEntitySuccess 里的那份。

重构目标：这里应该成为唯一的 Buff 添加入口（改为 public），然后在 OnShowEntitySuccess 回调里调用它。

重复 Buff 添加逻辑应该提取走

这个回调在实体创建完成后触发，是唯一能安全操作实体的时机。

紫线 玩家注册、AI 注入 — Procedure 的职责，应该留在这里。

绿线 血条和血量 — 目前也在这里，暂时可以接受。

黄线 根据 index 添加 Buff — 这和 SoldierFactory.AddInitialBuffs 完全相同。应该删掉这里的 switch-case，改为调用 SoldierFactory.AddInitialBuffs(soldierEntity, soldierEntity.UnitIndex)。
