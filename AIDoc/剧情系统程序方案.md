# 剧情系统程序方案

> 面向程序实现。**只看这一份即可确定要做什么**，不需要先读剧本。
> 剧情内容本身见《剧本大纲》《剧情方案》《三十关AVG梗概》。

---

## 一、必要背景

### 1.1 游戏结构

- 三章，每章约十关，共约 30 关。
- 关卡内部循环：**整备 → 进攻 → 整备 → 防御 → …**，每两个阶段为一天，一关约十天。
- 玩家控制一个英雄 + 一个初始阵营，打爆敌方据点即**自动收编**该阵营（无确认弹窗），获得其单位与科技的使用权。
- 一关会遭遇 3–5 个阵营，第一章全章共十个阵营。
- 局外已有：每关自选 3 个正面词条（`LevelTagTable`），负面词条无上限。

### 1.2 剧情的三个人物（程序只需知道有这三个说话人）

| 代号       | 身份                 | 在通讯中的表现                                                           |
| ---------- | -------------------- | ------------------------------------------------------------------------ |
| 【主任】   | 主角的研究院上级     | 第一章正常；第二章起**信号残缺**（文本缺损 + 杂讯）；第三章消失    |
| 【中间人】 | 封锁区外的黑市中间人 | 第一、二章正常；第三章**信号逐渐衰减**至几乎不可闻                 |
| 妹妹       | 主角要找的人         | 仅第三章出现在通讯位，**由断续单字逐步变为完整句子，最后出现立绘** |

### 1.3 已有可复用的基础设施

| 设施               | 位置                                                                                                                 | 说明                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| DataTable 代码生成 | `Assets/AAAGame/DataTable/`，xlsx 源在 `AAAGameData/DataTables/`                                                 | **新增配表会自动生成 cs，不要手改生成物**      |
| UI 框架            | `UIFormBase`，`SpawnItem<UIItemObject>(prefab, parent).itemLogic as T`                                           |                                                      |
| 数据模型与持久化   | `DataModel/`，`ProfileDataModel`（生涯进度，目前只有已弃用的 `BaseLevel`）、`InGameDataModel`（局内）       |                                                      |
| 流程               | `Procedures/`，`GameProcedure` / `GameOverProcedure` 等                                                        | 关后 AVG 需要插入流程                                |
| 关卡信息界面       | `UI/LvEnterDialog.cs`                                                                                              | 词条选择已实现，**通讯框与任务列表要加在这里** |
| 本地化             | `LocalizationTextDataModel.GetText(identifier)` 读表；`LocalizationTextManager.GetLocalizedText(key)` 读直接 key | **所有剧情文本走本地化 key**                   |
| 描述填值           | `DescriptionValueFormatter.LocalizeAndFill(descKey, values)`                                                       | 已用于词条描述，剧情文本的动态占位可参考             |
| 事件               | `GF.EventArgs`                                                                                                     |                                                      |
| 配置               | `GF.Config.GetInt(key, default)`                                                                                   |                                                      |

### 1.4 硬约束

- **无配音。** 战斗中的文本读不进去，所以**战斗过程中不放任何剧情文本**。
- 核心战斗数值用 `Fix64`，float 仅用于 Unity API / UI 边界。
- 剧情表现**不得阻塞或改变战斗玩法**，除一处例外（见 4.3）。

## 二、两类完全不同的剧情载体（不要混淆）

|      | **AVG**                            | **关前通讯框**                                                 |
| ---- | ---------------------------------------- | -------------------------------------------------------------------- |
| 位置 | 关卡结束后、结算前，独立全屏界面         | **关卡信息界面（`LvEnterDialog`）内的一个区域**              |
| 形态 | 静态立绘 + 背景 + 文本框，逐屏推进       | 两个并列的通讯框，各一段短对白                                       |
| 交互 | 逐字显示、点击推进、跳过、历史、自动播放 | 有头像和文本，打字机效果，文本支持滚动，**不阻塞界面其余操作** |
| 用途 | 剧情主战场，所有情节推进                 | 交代本关为什么要打，**任务列表由它总结而来**                   |
| 数量 | 每关一段（关后为主），约 33 段           | 每关两段（【主任】/妹妹 一段 + 【中间人】一段）                      |

**关前通讯框不是 AVG，不要用 AVG 播放器实现。** 它是关卡信息界面的常驻 UI 区域，玩家可以反复看、可以不看直接开始。

## 第一批 · AVG 播放器（其余全部依赖）

### 3.1 配表 `StoryScriptTable`（一行 = 一屏）

| 字段                          | 类型   | 说明                                                                      |
| ----------------------------- | ------ | ------------------------------------------------------------------------- |
| ID                            | int    |                                                                           |
| ScriptID                      | string | 段落归组标识，如`Story_L8`                                              |
| Order                         | int    | 段落内顺序                                                                |
| BgSpritePath                  | string | 背景图路径。**留空 = 沿用上一屏**                                   |
| PortraitLeft / Center / Right | string | 立绘路径，留空 = 该位无人；`-` = 清除该位                               |
| PortraitEmotion               | string | 差分标识（可选）                                                          |
| SpeakerKey                    | string | 说话人名（本地化 key），留空 = 旁白                                       |
| TextKey                       | string | 正文（本地化 key）                                                        |
| Style                         | enum   | `Normal` / `Document`（文档式排版，见 3.5）/ `Terminal`（设备界面） |
| Effect                        | string | 特效标记：`ShakeScreen` / `FadeOut` / `Glitch` 等，可空             |
| DynamicRef                    | enum   | 动态文本引用（见 5.1），默认`None`                                      |

### 3.2 配表 `StoryTriggerTable`（一行 = 一个触发点）

| 字段            | 类型   | 说明                                                                     |
| --------------- | ------ | ------------------------------------------------------------------------ |
| ID              | int    |                                                                          |
| LevelIdentifier | string | 关卡标识，如`Lv_8`。留空 = 非关卡触发（如游戏开场）                    |
| Timing          | enum   | `GameStart` / `BeforeLevel` / `AfterLevelWin` / `AfterLevelFail` |
| ScriptID        | string | 对应`StoryScriptTable.ScriptID`                                        |
| OnceOnly        | bool   | 是否只播一次（多数主线为 true，重玩不再播）                              |

### 3.3 `StoryUIForm`

功能要求：

- 文本**逐字显示**，点击一次跳到整句结束，再点一次进下一屏
- **跳过按钮**：跳过整段
- **快进**：已读过的段落可秒跳（依赖 3.6）
- **自动播放**：可开关，速度可调
- **历史记录回看**：滚动列表，显示已播过的屏
- 背景切换（淡入淡出）、立绘进出（左中右三位）
- 支持 `Style` 三种排版：普通对话框 / 文档式 / 设备终端式
- 支持 `Effect` 标记的简单表现

### 3.4 `StoryManager`（放在 `UTManagers/` 下）

```
PlayScript(string scriptID, Action onComplete)
bool HasRead(string scriptID)
```

**关键要求：必须能阻塞流程。** 关后 AVG 播完才进结算界面；播放期间不接受其他输入。挂接点在 `Procedures/` 中，需要在 `GameProcedure` → `GameOverProcedure` 之间插入播放步骤。

### 3.5 `Style` 三种排版

| Style        | 用途                                   | 表现                                                                  |
| ------------ | -------------------------------------- | --------------------------------------------------------------------- |
| `Normal`   | 常规对话与旁白                         | 底部文本框 + 立绘                                                     |
| `Terminal` | 主角在采集器上查东西（约 8 关用到）    | 全屏设备界面底图，等宽字体                                            |
| `Document` | 实验记录、档案（如"样本 07 调用日志"） | 打字机字体、行号/编号、**涂抹与删改痕迹**（部分行显示为被划掉） |

`Document` 是剧情里的重要表现手段，不能用普通对话框凑。

### 3.6 已读记录持久化

`ProfileDataModel` 现在只有 `BaseLevel` 一个 int 字段，需要扩展为可存**字符串集合**（已读 ScriptID）。

建议做法：在 `ProfileDataModel` 增加 `HashSet<string>` 字段并纳入 JSON 序列化，或另建 `StoryProgressDataModel`（`DataModelStorageBase` 子类）。

**里程碑**：这六项做完，先只做 L1、L2 两段真实内容，跑通"进关 → 关前通讯 → 打 → 关后 AVG → 结算"，验证格式与体感。

## 第二批 · 关前通讯框与任务列表

### 4.1 配表 `StoryCommTable`（关前通讯）

| 字段            | 类型   | 说明                                                                                    |
| --------------- | ------ | --------------------------------------------------------------------------------------- |
| ID              | int    |                                                                                         |
| LevelIdentifier | string | 关卡标识                                                                                |
| Slot            | enum   | `Primary`（主任 / 第三章为妹妹）/ `Secondary`（中间人）                             |
| SpeakerKey      | string | 说话人名                                                                                |
| PortraitPath    | string | 立绘                                                                                    |
| TextKey         | string | 对白正文                                                                                |
| SignalState     | enum   | `Normal` / `Corrupted`（残缺+杂讯）/ `Weak`（微弱）/ `Fragment`（只有零碎单字） |

**`SignalState` 是叙事的核心表现，不是装饰。** 它决定文本是否显示缺损、立绘是否加杂讯/半透明效果。三章的变化：

| 章 | Primary                              | Secondary          |
| -- | ------------------------------------ | ------------------ |
| 一 | Normal（章末最后一关转 Corrupted）   | Normal             |
| 二 | Corrupted                            | Normal             |
| 三 | 妹妹：Fragment → Normal → 出现立绘 | Weak → 几乎不可闻 |

### 4.2 `LvEnterDialog` 扩展

在现有词条选择界面上加两个区域：

1. **通讯区域**：两个通讯框并列，各显示一段对白（可折叠/展开、可重播）。**不阻塞界面其余操作。**
2. **任务区域**：三类并列——
   - 主线任务（本关胜负目标，读 `LevelTable` 的胜利/失败条件）
   - 探测目标（关卡预设挑战，每关 3–5 个，完成打勾）
   - 支线委托预告（本关可接的委托类型与回报）

**任务列表是通讯内容的总结**：玩家跳过对白也能靠列表打下去。所以任务文本独立配置，不从对白解析。

### 4.3 唯一一处玩法层的剧情强制

**第二章第一关（L16）禁用收编能力。** 需要在关卡配置上加一个开关字段（`LevelTable` 加列或走 `LevelTagTable` 的机制），使该关无法收编阵营。

**全游戏仅此一处。**

## 第三批 · 局内剧情表现（需先验证，见第七节）

### 5.1 动态文本引用 `DynamicRef`

AVG 文本需要支持运行时变量替换。目前已知需求：

| 枚举值                       | 含义                                       | 用在哪                                    |
| ---------------------------- | ------------------------------------------ | ----------------------------------------- |
| `None`                     | 无                                         | 默认                                      |
| `LastCapturedFactionVoice` | **本关最后收编的阵营的战斗语音台词** | L8 那份实验记录的最后一句（"这句不是她"） |

实现：`InGameDataModel` 记录本关收编顺序；`StoryUIForm` 渲染文本时按 `DynamicRef` 取值替换占位符。可参考 `DescriptionValueFormatter.LocalizeAndFill` 的做法。

**这条不能省** —— 它是 L8 那一击的全部效果来源：玩家几分钟前刚在战场上听过那句话。

### 5.2 关卡结算的阵营对白

结算界面显示**当前编制中随机一家**的一条对白。

需要：结算时可取到编制列表 + 一张阵营对白表（可加在阵营/单位相关表上，每阵营一条起）。

### 5.3 阶段切换日志（**待验证**）

阶段切换时显示一行主角日志。**只跟天数走，不跟玩家行为走**（避免接大量状态判断）。

分池随机抽：`章(3) × 天数段(前/中/后)` = 9 池，每池 6–8 条，同关内抽过不重复。总量约 40–50 行。另有 3–4 个关键关卡走专属文本。

> ⚠️ **表现形式未定，实现前必须先做效果验证。** 见第七节。

### 5.4 造兵营短语（**待验证**）

在造兵营建造反馈中显示该阵营的一句话（十余字）。

可在 `BuildingTable` 加一列，或复用现有描述位。

> ⚠️ **表现形式未定，实现前必须先做效果验证。** 见第七节。

## 第四批 · 委托系统

### 6.1 救援委托（常规，每关可有）

- 关内出现一个待救 NPC（平民模型，1–2 套复用）
- **撤离时限按天数计**：到指定天数未送出，该 NPC **当关转为敌方单位**（改用现有阵营美术），无任何回报
- UI：小地图与场景标记、剩余天数倒计时、超时转敌的明确反馈
- 回报（救出时）：适配度、收集品、情报（解锁收集条目）
- **不得影响关卡难度**：兵力配置、敌方强度、地图均不因委托而变

### 6.2 信物委托（章节级，全作 6 个中的 4 个走委托）

**一个人一种完成方式，由他的故事决定**，不是多选。四种形态：

| 关  | 执念             | 完成方式       | 需要的关内目标类型                                           |
| --- | ---------------- | -------------- | ------------------------------------------------------------ |
| L5  | "把这批货送到"   | **护送** | 护送并保护特定单位（**目标自己动**，玩家不能控制路线） |
| L9  | "不能让人进来"   | **守住** | 占领并守护地标（若干天）                                     |
| L13 | 已无内容，只剩痛 | **击杀** | 击杀特定单位                                                 |
| L23 | "把人找回来"     | **带回** | 营救特定单位（护送回目标处，可复用救援委托逻辑）             |

另两个信物是主线自动获得（L17 妹妹、L26 主任），无委托。

详见《关卡目标设计》第六节。

### 6.3 委托配表与结算

- `QuestTable`：委托 ID / 所属关卡 / 类型 / 时限 / 目标参数 / 回报
- 完成状态存 Profile
- 产出：适配度、信物、收集品解锁

## 第五批 · 局外成长与解锁

### 7.1 适配度（局外经验）

**设定**：主角对污染环境的耐受程度。**不是"变强"，而是被同化的进度** —— 表现基调应略带侵蚀感，不做成纯正面。

产出：

| 来源                 | 规则                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------ |
| 关卡通关             | 基础值                                                                                                       |
| **偏移率加成** | 按本关所选负面词条`Score` 求和，**平方曲线转倍率**：`倍率 = 1 + k × 偏移率²`，**不设上限** |
| 支线委托完成         | 每个固定值                                                                                                   |
| 首次通关某关         | 一次性额外                                                                                                   |

注：各项经验值需要配表。

消耗：**升级只解锁新的正面词条，不提升任何数值。每关仍然只能选 3 个。** 成长是选择空间变宽，不是变强。

### 7.2 配表改动

| 表                                  | 改动                                                             |
| ----------------------------------- | ---------------------------------------------------------------- |
| `LevelTagTable` 正面词条（31 条） | 补填`UnlockLevel`；`Score` **保持为空**（正面无分值）  |
| `LevelTagTable` 负面词条（74 条） | `UnlockLevel` 全部改为开局解锁                                 |
| 新增等级表                          | 等级 → 所需适配度 → 解锁的词条 ID 列表                         |
| 新增禁用清单                        | 各关禁用的负面词条（现有`ExceptLevelID` 可能够用，需确认语义） |

### 7.3 信物槽

- `LvEnterDialog` 增加**独立特殊槽**，不占用 3 个词条名额
- 全作 6 个信物，**影响英雄的攻击动作与初始技能** → 需接入英雄技能/动作系统
- 妹妹的信物有**四段外观状态**（残缺 → 逐渐修复 → 结局A重新破损 / 结局B完全完整），需要一个进度字段驱动外观切换

### 7.4 两套不同的表现 UI（不要混为一套）

**① 适配度获取与升级 —— 结算流程的一部分**

位置：关卡结算界面。表现的是一个**连续的数值过程**：

- 本关获得的适配度明细（基础值、偏移率倍率、委托奖励、首通额外）
- 进度条增长动画
- 达到阈值时的升级提示

基调**不做成纯正面的"变强"**，可略带侵蚀感——它是主角被同化的进度。

**② 解锁展示 —— 一套复用**

以下三种共用同一套表现流程（获取动效 + 展示面板 + 说明文本）：

1. 升级解锁的正面词条
2. 解锁收集品
3. 获得信物 / 信物外观变化

建议做成 `UnlockPresentUIForm` + 统一的 `UnlockPayload`（图标、标题、描述、类型），由各系统投递。**这三种不要各写一套 UI。**

**①在结算内联播放，②是独立弹出的展示。** 升级时可由①触发②（升级 → 弹出本次解锁的词条）。

## 七、两处必须先验证的表现（不要直接实现）

以下两项**设计意图是"零成本增加风味"，但很可能起负面作用**，实现前必须先做小规模验证。

### 7.1 阶段切换日志

**担忧**：阶段切换是玩家想快速推进的时刻。此时弹一行与当前战况无关的主角内心独白，可能被感知为"每天都要看一句废话"，尤其在一关十天、三十关的重复量下。

**验证方式**：做 3–5 条真实文本接进去，连打两关，判断：

- 它是否延长了阶段切换的等待感
- 十天下来是否形成了情绪曲线，还是变成噪音
- 玩家会不会开始无视它

**如果效果不好的备选**：

- 只在**每关的固定几天**出现（如第 1、5、10 天），而不是每次切换
- 完全砍掉

### 7.2 造兵营短语

**担忧**：短语的目的是让玩家意识到"这些兵是些什么人"，但建造反馈是功能性极强的位置，玩家关心的是造好了没有。一句台词可能被完全忽略，或者反过来干扰功能读取。

**验证方式**：接 2–3 个阵营的短语，判断：

- 玩家是否真的会读
- 是否影响建造操作的流畅度
- 重复建造同一建筑时，同一句话重复出现是否廉价（**需要考虑一个阵营配多句轮换**）

**如果效果不好的备选**：

- 改放在**首次建造该阵营的建筑时**出现一次（而非每次）
- 改放在单位首次部署时
- 完全砍掉，风味全部由档案与场景承载

**在验证通过前，这两项按"预留接口、不填内容"处理。**
