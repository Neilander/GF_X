# 卡牌丢弃功能修复说明

## 修复时间
2025-04-12

## 问题描述
卡牌拖动到垃圾桶位置时，没有被丢弃，而是在该位置生成士兵对象。

## 根本原因

### 1. 坐标转换问题
原始代码使用 `GetWorldCorners` + `WorldToScreenPoint` 来计算垃圾桶的屏幕坐标边界，但这种方法在不同 Canvas 模式下会产生错误的结果：

- **Overlay 模式**: `GetWorldCorners` 返回的是 Canvas 空间坐标（非常大的数值），不是屏幕坐标
- **Camera 模式**: 需要使用正确的相机进行转换

从日志可以看到，垃圾桶边界坐标异常：
```
Bounds: (175133.5,34930.18) to (198738.5,44125.82)
```
而鼠标位置只有：
```
Screen pos: (1714.57, 362.22)
```

这导致检测永远返回 false。

### 2. 检测优先级问题
原始代码的检测顺序：
1. 检查是否在手牌区域
2. 检查是否在垃圾桶区域
3. 尝试放置到场景

但由于垃圾桶检测失败，卡牌总是进入第 3 步，导致生成士兵。

## 修复方案

### 1. 简化坐标检测
使用 Unity 官方推荐的方法 `RectTransformUtility.RectangleContainsScreenPoint`，并根据 Canvas 模式选择正确的相机：

```csharp
private Camera GetUICamera()
{
    Canvas canvas = GetComponentInParent<Canvas>();
    if (canvas == null) return null;
    
    if (canvas.renderMode == RenderMode.ScreenSpaceOverlay)
    {
        // Overlay 模式不需要相机
        return null;
    }
    else
    {
        // Camera 模式使用 Canvas 的相机或 UICamera
        return canvas.worldCamera ?? GFBuiltin.UICamera;
    }
}

private bool IsInTrashBin(Vector2 screenPosition)
{
    if (m_TrashBinRect == null) return false;
    
    Camera cam = GetUICamera();
    return RectTransformUtility.RectangleContainsScreenPoint(
        m_TrashBinRect, screenPosition, cam);
}
```

### 2. 调整检测优先级
新的检测顺序（更合理）：
1. **优先级 1**: 检查是否在垃圾桶区域 → 丢弃卡牌
2. **优先级 2**: 检查是否在手牌区域 → 取消放置
3. **优先级 3**: 尝试放置到场景 → 生成对象

这样确保垃圾桶检测优先于场景放置。

## 额外优化

### 1. 统一相机获取
所有 UI 区域检测都使用 `GetUICamera()` 方法，确保一致性。

## 注意事项

1. **Canvas 模式**: 确保 Canvas 的 Render Mode 设置正确
2. **垃圾桶配置**: 确保 trashBin 对象在 Inspector 中已配置
3. **层级顺序**: 垃圾桶应该在 UI 层级的顶部，确保可以接收到拖拽事件
