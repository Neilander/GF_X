**影响文件**:

## 技术说明

### 为什么使用 UIItemObject 而不是 HandCardItemObject？

虽然 `HandCardItemObject` 继承自 `UIItemObject`，但由于编译顺序和命名空间的问题，直接使用基类 `UIItemObject` 更加稳定和可靠。这不会影响功能，因为：

1. 对象池系统会正确创建和管理对象
2. `gameObject` 属性可以访问到实际的 GameObject
3. 通过 `GetComponent<HandCardItem>()` 可以获取到正确的组件

### UIItemObject 的结构

```csharp
public class UIItemObject : ObjectBase
{
    public GameObject gameObject { get; private set; }
    public UIItemBase itemLogic { get; private set; }
    
    // ... 其他方法
}
```

关键属性：
- `gameObject`: 实际的 GameObject 实例
- `itemLogic`: UIItemBase 组件引用
