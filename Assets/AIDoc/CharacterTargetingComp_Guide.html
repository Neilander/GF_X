① ITargetingComp 接口定义（ITargetingComp.cs）
public interface ITargetingComp : ICapability
{
    void Init(IEntityContext ctx);
    void UpdateTargeting(float deltaTime);

    // 供外部（如 AI Brain 或 UI）读取的当前目标
    IEntityContext CurrentTarget { get; set; }
    IEntityContext FollowTarget  { get; }

    // 索敌和遗忘半径
    float AggroRange       { get; set; }
    float ForgetRange      { get; set; }
    float FollowSearchRange{ get; set; }
}

架构 接口即契约

这个接口定义了 所有 Targeting 组件必须实现的能力，继承自 ICapability，说明它是 Entity 的"可插拔能力"之一。

蓝色 两个目标属性：

  • CurrentTarget — 当前锁定的敌人（可读可写，Brain 可以强制覆盖）
  • FollowTarget — 跟随对象（只读，只由组件自己维护）

黄色 三个距离参数：由工厂的 SO 注入初始值，运行时也可改。

核心 数据结构总览

蓝色 _ctx — 自身 Entity 的上下文引用，通过它读取自身位置、阵营等信息。这是 所有逻辑的基础。

黄色 三个距离参数（默认值仅是后备，实际由工厂 SO 覆盖）：

  • AggroRange = 6 — 索敌半径
  • ForgetRange = 8 — 遗忘半径（> 索敌，形成滞后区间）
  • FollowSearchRange = 30 — 跟随搜索范围

红色 降频计时器：每 0.2 秒 才做一次全量扫描，避免每帧遍历全部实体。这是性能优化的关键。

③ Init — 初始化
public void Init(IEntityContext ctx)
{
    _ctx = ctx;
    CurrentTarget = null;
    FollowTarget  = null;
    _scanTimer    = 0f;
}

绿色 干净的初始化

做三件事：

  1. 保存 Entity 上下文引用
  2. 清空两个目标
  3. 重置扫描计时器

注意：Init 后还需要工厂设置 AggroRange / ForgetRange，这两步在 Factory 里顺序执行（先 Init → 再赋值）。

核心 "遗忘"机制

每帧检查已有的敌人目标是否还有效：

  • 红色 超出 ForgetRange → 丢失目标
  • 红色 目标死了 → 丢失目标

⚠️ 设计要点：ForgetRange(8) > AggroRange(6)，形成 滞后区间——不会出现"刚锁定就丢失"的抖动现象。这是经典的"迟滞比较器"思路。

⑥ 维护跟随目标（每帧执行）

    if (FollowTarget != null)
    {
        float dist = Vector3.Distance(_ctx.Position, FollowTarget.Position);
        if (dist > FollowSearchRange || !FollowTarget.Alive)
            FollowTarget = null;
    }

逻辑 跟随目标失效判定

和敌人目标的维护完全对称：

  • 距离超出 FollowSearchRange(30) → 放弃跟随
  • 跟随对象死亡 → 放弃跟随

注意这部分是 每帧都执行 的——维护阶段不受降频影响，保证丢失目标的反应是即时的。

绿色 性能优化：降频

SCAN_INTERVAL = 0.2s，即 每秒最多扫描 5 次，而不是每帧 60 次。

为什么这么做？ 下面的扫描要遍历 EntityRegistry.AllEntities，是 O(n) 操作。如果场上有 200 个实体，每帧每个实体都扫一遍 = 200×200×60 = 240 万次/秒。降频后变成 200×200×5 = 20 万次/秒，减少了 12 倍。

⑧ 扫描最近敌人
        // 找敌人：遍历 EntityRegistry，按阵营和距离
        if (CurrentTarget == null)
        {
            IEntityContext nearest = null;
            float nearestDist = AggroRange;
            var all = EntityRegistry.AllEntities;
            for (int i = 0; i < all.Count; i++)
            {
                var other = all[i];
                if (other == _ctx || !other.Alive) continue;
                if (other.Side == _ctx.Side || other.Side == SideType.NoSide) continue;

                float dist = Vector3.Distance(_ctx.Position, other.Position);
                if (dist < nearestDist)
                {
                    nearestDist = dist;
                    nearest = other;
                }
            }
            CurrentTarget = nearest;
        }

核心 索敌算法

只在 CurrentTarget == null 时才搜索（已有目标就不换人，保持"粘性"）。

绿色 遍历策略：

  • 用 for 而非 foreach 避免 GC
  • 用 nearestDist 初始化为 AggroRange，同时做"最近"和"范围内"两重筛选

红色 过滤条件（易错点！）：

  • other == _ctx — 排除自己
  • !other.Alive — 排除已死亡实体
  • other.Side == _ctx.Side — 排除友军
  • other.Side == NoSide — 排除中立实体（如场景物件）

💡 注意：这里没有用 Physics.OverlapSphere，而是直接遍历全局注册表 + 距离判断。适合实体数量可控的场景。

⑪ CharacterTargetingFactory — 工厂实现
[CreateAssetMenu(fileName = "CharacterTargetingFactory",
                menuName = "Targeting Factory/CharacterTargeting")]
public class CharacterTargetingFactory : TargetingCompFactory
{
    [Header("默认索敌配置")]
    public float defaultAggroRange  = 6f;
    public float defaultForgetRange = 8f;

    public override ITargetingComp CreateTargetingComp(MAEntity gmo)
    {
        var comp = new CharacterTargetingComp();
        comp.Init(gmo);

        // 赋予初始面板值
        comp.AggroRange  = defaultAggroRange;
        comp.ForgetRange = defaultForgetRange;

        gmo.SetTargetingComp(comp);
        return comp;
    }
}

工厂 ScriptableObject 注入模式

紫色 CreateAssetMenu — 可以在 Unity 编辑器中右键创建这个 SO 资产。

黄色 面板可配参数：策划可以在 Inspector 里调整索敌/遗忘半径，不用改代码。

绿色 创建流程：

  1. new CharacterTargetingComp()
  2. Init(gmo) — 注入上下文
  3. 覆盖默认参数
  4. SetTargetingComp — 注册到 Entity 上

⚠️ 注意和 NoTargetingFactory 的区别：它的 Init 和 SetTargetingComp 调用顺序是 反的（先 Set 再 Init），可能是个隐患。

⑫ TargetingCompFactory — 工厂基类
public abstract class TargetingCompFactory : ScriptableObject
{
    public abstract ITargetingComp CreateTargetingComp(MAEntity gmo);

    // 统一的资源加载回调
    public static LoadAssetCallbacks TargetingFactoryCallBack =
        new LoadAssetCallbacks(
            (assetName, asset, duration, userData) =>
                (asset as TargetingCompFactory)?.CreateTargetingComp(
                    userData as MAEntity));
}

架构 抽象工厂 + 异步加载

蓝色 抽象基类只定义一个方法：CreateTargetingComp。所有具体工厂（Character / NoTargeting）都继承它。

紫色 TargetingFactoryCallBack — 这是给 GF 资源管理框架的加载回调。流程：

  1. Entity 初始化时请求加载 SO 资产
  2. 资源管理器异步加载完成 → 触发此回调
  3. 回调中将 asset 转型为工厂 → 调用 CreateTargetingComp
  4. userData 携带了目标 Entity 引用

这种模式让 Entity 不需要知道具体用哪个工厂，只要配好 SO 资产路径即可。
